## 観点別結果

### 観点1: 起動直後に水平スクロールバーが出ぬこと＝全20列が見えること

**NG**。水平ScrollBarは依然として存在し（`ScrollBar count: 2`＝垂直・水平各1件）、
`RangeValue.Maximum = 7.50393700787413`（実測、ゼロではない）。ごくわずかだが未解消。

### 観点2: 描画エリアの実幅——理論値858pxとの突合

- `CanvasArea`実測: `Bounds=2201,202,858,435` → **Width=858px、家老の理論値858pxと完全一致**
- ただし水平ScrollBar自体の実測幅は841px（`Bounds=2201,620,841,17`）。ScrollBar自身が場所を取る分
  （858−841=17px）を差し引いた**実効ビューポート幅は841px**であり、これが実際に列を表示できる幅。
- コンテンツ全体幅を実測ベースで逆算すると 841(ビューポート) + 7.5(Maximum) = **848.5px**。
  T-127着手前の忍者調査時の理論値849px・実測848.5pxと完全に一致しており、**シート自体の必要幅は
  変わっていない**（当然だが確認できた）。
- **収まらなかった理由**：CanvasArea全体幅858pxは理論必要幅849pxを上回るが、水平ScrollBarが
  一度出現するとその分（17px）だけビューポートが狭まり、841px<849pxとなって「あと一歩」収まらない
  状態が自己撞着的に残る。858px確保しても、スクロールバーの分だけ実効幅が目減りする構造。

### 観点3: 左パネルの実幅——保存レイアウト復元により212px相当のままであることの確認

**確認できた（侍の見立てどおり）**。`SheetNavList`実測: `Bounds=1978,205,212,399` →
**Width=212px**。T-127着手前の調査時と全く同じ値であり、侍がXAML側に指定した190pxは反映されて
いない。`%AppData%\Ecad2\docking-layout\main-layout.xml`の保存済み`DockWidth="220"`
（実測212px相当）がXAML既定値を上書きしている、という侍の下調べどおりの結果。

### 観点4: ウィンドウ幅が1400pxになっていること

**確認済み**。`Get-Ecad2WindowRect`実測: `Width=1400px, Height=800px`
（`Left=1960,Top=40,Right=3360,Bottom=840`）。

### 観点5: P-131（横幅変更で垂直スクロールMaximumが変わる件）参考情報

今回はリサイズ操作（モニタ移動を伴う`Resize-Ecad2Window`）を行わず、起動直後の状態のまま計測した。
垂直ScrollBarの`RangeValue.Maximum = 73.2585826771655`——これはT-127着手前調査の**初回起動時**
（リサイズ前）の値と完全に一致する。前回P-131が観測されたのは「`Resize-Ecad2Window`でモニタを
またいで移動した後」のみであり、**モニタ移動を伴わない限り値は変化しない**可能性が高いと見られる。
本筋（T-127判定）を優先しリサイズは行っていないため、これ以上の深追いはせず参考情報に留める。
