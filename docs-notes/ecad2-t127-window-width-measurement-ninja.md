# T-127 起動時ウィンドウ横幅の実測調査（忍者）

日付: 2026-07-27
task_id: T-127（殿直接ご要望「アプリ起動時の横幅について。描画エリアは基本的に固定値になるはずだが
全部表示されていない。広げられないか」）

## 検証手法

- `ecad2-ui-automation`スキルに従い、セカンダリモニタでEcad2.Appを起動
- 機械的判定を優先し、目視でなくUIAの`BoundingRectangle`・`RangeValuePattern`の数値採取で測定
- コード側の起動時サイズ決定箇所・グリッド列数定数はExploreエージェントへ調査委任、実測値との
  クロスチェックに用いた
- シート追加ボタン・ダイアログOKボタンはいずれもUIA `InvokePattern`経由（物理クリックではない）
- 検証後、シートは1枚残るが未保存のまま`Stop-Ecad2App`で終了。ファイルへの影響なし

## DoD-1: 起動直後のウィンドウ幅・クライアント領域幅

- ウィンドウ外形（実測、`Get-Ecad2WindowRect`）: **Width=1280px, Height=800px**
- メニューバー内側の実効幅（クライアント領域相当の参考値、`MenuBarArea`のBoundingRectangle）:
  幅1264px（ウィンドウ外形との差16pxはウィンドウ枠相当）

## DoD-2: 描画エリアの実表示幅と全列表示に要する幅

- 描画エリア（`CanvasArea`）実表示幅（Pane全体、水平スクロールバー分含む）: **738px**
- 水平スクロールバー自体の幅（ビューポート実効幅に近い値）: 721px
- 全列（20列）表示に要する幅:
  - **理論値（Explore調査）**: `MarginMm(20) + 20列×CellMm(9.0) + BusPad(4.5) + MarginMm(20)`
    = 224.5mm × (96/25.4 DIP/mm) ≒ **849px**
  - **実測値**（水平ScrollBarの`RangeValuePattern`から逆算）: ビューポート721px + Maximum127.5px
    = **848.5px**
  - **理論値と実測値がほぼ完全一致**（クロスチェック成立）

## DoD-3: 不足量

- **127.5px**（実測、水平ScrollBarの`RangeValue.Maximum`値、起動直後の状態）
- 列数換算: 1列 ≒ 34.0px（CellMm9.0 × MmToDip3.7795）として、**約3.75列分**
- **実機での裏付け**: `Resize-Ecad2Window`でウィンドウ幅を1280px→1430px（+150px）に拡大したところ、
  水平スクロールバーが消滅（20列全てがスクロールなしで表示可能になったことを実機確認）。
  必要最小限は理論上+127.5px程度、安全マージンを見込むなら+140〜150px程度が妥当と見られる。

## DoD-4: 起動時サイズの決定箇所

- `src/Ecad2.App/MainWindow.xaml:12`
  ```xml
  Title="ecad2" Height="800" Width="1280" WindowStartupLocation="CenterScreen"
  ```
- `SizeToContent`属性は指定なし（既定値Manual）。コードビハインドでのWidth/Height上書きも無し
  （Explore調査でgrep該当なし）。起動時サイズはXAML固定値のみで決まる。

## DoD-5: 描画エリア以外の横幅の食われ方

起動直後（拡大前）の内訳、ウィンドウ全体1280px中:

| 領域 | 指定値（XAML） | 実測値 |
|---|---|---|
| 左パネル（`SheetNavList`、シート一覧） | `DockWidth="220"`（`MainWindow.xaml:1346`） | 212px |
| 描画エリア（`CanvasArea`） | 指定なし（残り全幅=Star相当） | 738px |
| 右パネル（`DeviceTableGrid`+`PartSelectionList`縦分割） | `DockWidth="280"`（`MainWindow.xaml:1476`） | 272px |
| 枠・スプリッター等の残り | - | 約58px |

拡大後（Width=1430px）は左右パネル幅は不変のまま、描画エリアのみ738px→888px（+150px、指定した
拡大量と完全一致）に増加した。左右パネルはAvalonDockの`DockWidth`固定、描画エリア
（`LayoutDocumentPane`）のみがStar相当で残り幅を占有する構造のため、ウィンドウ幅拡大分は
そのまま描画エリアの拡大に反映される。

## 対処案（採否は殿裁可事項、DoDには含めないが参考まで）

1. **`MainWindow.xaml:12`のWidth既定値を1280→1420程度へ拡大**。最もシンプル、実機で効果を確認済み
   （既に実機で+150pxにて全列表示を確認）。
2. `SizeToContent`系（コンテンツに応じた自動調整）は、現状シート列数が実質固定20だが将来UIで
   可変になった場合に硬直するリスクがあるため、固定値拡大の方が無難と見る。
3. 左右パネルのDockWidth縮小（220/280→もっと狭く）は、シート一覧・機器表の使い勝手とのトレード
   オフになる。

## 範囲外の気づき（家老・殿判断向け、忍者から着手はせず）

- **`Resize-Ecad2Window`の副作用でウィンドウがセカンダリモニタからプライマリモニタへ移動する事象を
  確認**（既存スキル文書に記載なし、新規の可能性）。`MoveWindow`がモニタ境界をまたぐ座標を渡すと
  発生すると見られる。直後に`Move-Ecad2WindowToScreen -Screen Secondary`で復帰済み、影響は最小限に
  留めた。今後リサイズ検証を行う際は、直後に必ずウィンドウ位置（モニタ）を確認する一手間を推奨する。
- ウィンドウ横幅拡大に伴い、垂直スクロールバーの`RangeValue.Maximum`が73.26→56.26へ変化した。
  横幅と無関係のはずだが原因未特定。今回の主題（横幅不足）とは別件のため深追いしていない。
