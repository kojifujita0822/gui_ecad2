# T-129 `Stop-Ecad2App`改修版 実地確認（忍者）

日付: 2026-07-27
対象コミット: `d993932`（正規終了を既定へ、フォールバック追加）

## 検証手法

- `ecad2-ui-automation`スキルの改修版`Stop-Ecad2App`を実際に呼び出し、戻り値の文字列と
  `main-layout.xml`の更新時刻（`stat -c "%y"`）を突き合わせて判定
- 判定は数値（時刻・所要時間）中心、目視は不要だった

## 観点別結果

### 観点1: 起動中の正規終了が実際に効くか

**OK**。未保存の変更がない状態（シート追加等を一切行わず）で起動直後に`Stop-Ecad2App`
（引数なし）を実行 →
- 戻り値：`Ecad2.App stopped (graceful close)`
- `main-layout.xml`の更新時刻：実行前`10:52:50`→実行後`10:55:54`（**実行タイミングと一致、
  終了時保存が実際に走ったことを確認**）
- `DockWidth="190"`のまま、内容も正しい

### 観点2: フォールバックが実際に働くか

**OK**。シートを1件追加し保存していない状態（Dirty）を作り、`Stop-Ecad2App`（引数なし、
既定タイムアウト5000ms）を実行 →
- 戻り値：`WARNING: Ecad2.App を強制終了した(正規終了が効かず)。終了を 5000ms 待っても完了せず
  (未保存確認ダイアログ等でブロックされている可能性) 。終了時の保存処理(SaveDockingLayoutAsDefault等)
  は走っておらぬ`
- 所要時間：**5733ms**（既定タイムアウト5000ms＋オーバーヘッド、想定どおり）
- `main-layout.xml`の更新時刻：実行前後とも`10:55:54`で**不変**（終了時保存が走っていないことを
  裏付け）
- プロセス完全終了を確認済み（強制終了も成功）

未保存確認ダイアログを明示的に操作する必要はなく、`Stop-Ecad2App`を呼ぶだけで
「ブロック→タイムアウト→強制終了」の一連の流れが内部で自動的に発生することを確認した。

### 観点3: 引数なしで従来どおり呼べること

**OK**。観点1・2いずれも引数なし（`Stop-Ecad2App`のみ）で呼び出し、正しく動作した。
既存呼び出し元の互換は保たれている。

### 観点4: 使い心地

- 戻り値の文字列が理由（`reason`）まで含めて丁寧で、診断に役立つ（`WARNING:`で始まるかどうかを
  見るだけで保存が走ったか一目で判別できる、という設計意図どおり機能している）
- フォールバック発生時は既定タイムアウト分（約5.7秒）待つため、素早く終了させたい場面では
  やや長く感じるかもしれないが、これは安全性（未保存確認ダイアログを強引に握り潰さない）との
  トレードオフであり妥当な設計と判断する
- P-135（例外発生後にプロセスが偶然自然終了した場合の経路、隠密・家老とも修正不要合意済み）は
  今回の観点1・2どちらの経路でも踏まなかった（正常系・タイムアウト系のみを通った）

## 総評

改修版は設計意図どおりに動作している。**旧実装の罠（関数そのものが終了時保存を握り潰す）は
解消され、新しい罠（戻り値の`WARNING:`を読み落とす）に置き換わった**という侍の総括どおりの
性質で、実機でもそのとおりの挙動を確認できた。SKILL.md§3の但し書き更新（Stop-Ecad2Appを
避けるべきという記述の削除）も、今回の実測結果と整合している。

## 操作手法

`Stop-Ecad2App`関数呼び出し（内部で`WindowPattern.Close()`または`Stop-Process -Force`を使用）。
UIA直接操作・物理クリックは今回使用していない。
