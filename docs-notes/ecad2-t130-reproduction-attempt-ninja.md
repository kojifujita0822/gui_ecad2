# T-130 シートパネル位置ずれ 実機再現確認（忍者）

2026-07-27。隠密調査書`docs/ecad2-t130-sheetpanel-position-shift-investigation-onmitsu.md`
4節の手順に基づく実機再現確認。**家老指示どおり「再現するか否かの一点」に絞り、無理な深追いはせず**。

## 結論

**4パターン試行、いずれも再現せず**。シートパネルは毎回、正しい位置（左パネル、DockWidth=190相当）
へ復元された。

## 試行内容

隠密仮説の核＝「AutoHide中にCollectGarbage()を誘発する操作が挟まると、解除時に元の位置を
見失う」。この「誘発する操作」の候補を4パターン変えて試した。

| # | 手順 | 結果 |
|---|---|---|
| 1 | シートAutoHide化 → 配置ツールバーをフロート化 → シートAutoHide解除 | **正常復元** |
| 2 | シートAutoHide化 → 「既定レイアウトに戻す」実行 → （AutoHide状態自体が強制解除され検証にならず） | AutoHide自体がクリアされ、この手法では検証不能と判明 |
| 3 | シートAutoHide化 → アプリ正規終了（`Stop-Ecad2App`）→ 再起動（`Start-Ecad2App`）→ シートAutoHide解除 | **正常復元**（隠密が「最有力」と見立てた条件だったが不再現） |
| 4 | シートAutoHide化 → 配置ツールバーをフロート化 → フロートウィンドウを×で閉じる（配置ツールバー自体が消失） → シートAutoHide解除 | **正常復元** |

## 副次所見（範囲外）

パターン4で、配置ツールバーのフロートウィンドウを閉じたところ、**配置ツールバー自体が
「配置ツール」タブごと消失**した（再表示の手段は今回試していない）。これはT-130の検証観点
外だが、フロートウィンドウの×ボタンが単なる「閉じる」であり「ドックへ戻す」動作ではない
ことを示す挙動。範囲外の気づきとして申し送る（落とし先は家老判断、AvalonDockのCanClose設計
に関わる可能性）。

## 検証環境の後始末

- `%AppData%\Ecad2\docking-layout\main-layout.xml`は検証前に
  `sample\t130-layout-backup\main-layout.xml.bak-20260727-t130`へ退避（`Copy-Item`のみ、
  `rm`不使用）
- 検証終了後、アプリ正規終了（終了時保存が走ることを踏まえ）→ **退避ファイルを`Copy-Item`で
  復元済み**。復元後の中身を確認、`DockWidth="190"`・シート正常位置であることを確認済み
  （殿の環境は無傷）

## 操作手法

- AutoHide化・解除：メニュー「表示(V)」→「パネルを自動的に隠す(A)」→「シート(S)」（トグル）、
  および解除はAutoHideタブのフライアウト表示後、ピン留めボタンを座標クリック
  （`Invoke-Ecad2ScreenClick`、UIA要素としてピン留めボタンが拾えなかったため座標特定して実施）
- アプリ再起動：`Stop-Ecad2App`（正規終了）→`Start-Ecad2App`
- いずれも合成マウスイベント（`Invoke-Ecad2ScreenClick`）またはUIA `ExpandCollapsePattern`経由、
  殿の実操作は使用せず

## 申し送り

**再現条件は依然不明のまま**。隠密仮説（`ToggleAutoHide()`のnull分岐＋`CollectGarbage()`の
`PreviousContainer`強制クリア）自体は一次ソース上成立する経路として否定されていないが、
今回試した4パターンの誘発操作では踏み抜けなかった。他に試す価値がありそうな操作列があれば
（例：AutoHide中に他パネルもAutoHide化する、複数回のFloat/Dock往復、シート追加・削除を挟む等）、
家老・隠密の判断を仰ぎたい。**忍者としてはここで一旦打ち切り、無理な深追いはしない**
（家老指示どおり）。
