   6.2「反映されない」かで一呼吸迷う）。**隠密が自分で通読していれば「正しく書けておる」で終わっていた。**
   対処は6.0節へ一行足すだけ。**制度化済み**＝`memory: feedback_author_taxonomy_vs_user_search_axis`
2. **ヘルパー関数の副作用が文書化されていなかった事故**——`Stop-Ecad2App`は`Stop-Process -Force`ゆえ
   `Window_Closing`を経由せず、**終了時保存が走らない**。T-128検証で**殿の`main-layout.xml`に検証中の
   一時配置が残留**（忍者が直後に気づき復旧）。**忍者は「己の見落とし」と報じたが、スキルに但し書きが
   無かった以上、落度は罠を書き残さなかった我ら全員にある**——この見立てを家老から伝えた
3. **「重複」の定義で侍と隠密が真っ向から食い違った**（T-126）——侍「実害の条件で引け」／隠密「重複の
   定義で引け」。**争点を「同一BoundaryOffset・異なるRowOffsetの正常な部品は実在するか」の一点に
   絞り込み**、侍の実測（`NetlistBuilder.Build`実走5ケース）が決着させた。**正確な実害条件は
   「全ポートの`BoundaryOffset`が同一」であって「2点が一致」ではない**——この切り分けで両者の主張が
   矛盾なく統合された。**片方だけでは実害を取りこぼすか正常な部品を弾くかに倒れていた**
4. **家老の落度2件**：(a)T-126の回帰確認で「実運用パーツ15件」と大雑把に振り、忍者が1件ずつ回す羽目に
