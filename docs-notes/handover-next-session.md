殿ご裁可＝矢印は案A（撮影も焼き込みもスクリプトで自動）／絵は5題（画面全体の構成・配置の流れ・

済んだ所・途中の所・次の一手は`docs/todo.md`のT-173節に書いてある。要点のみ記す。

- 増分1（変換器の画像対応）は実装とテスト済み。`![説明](images/xxx.png)`を行単位で書けば絵になる。
  絵は`docs/usage/images/`に置けばcsprojのワイルドカードで埋め込まれる。
  ただし絵を1枚も置いておらぬゆえ、使い方ウィンドウに絵が出る所はまだ誰も見ておらぬ。
- 増分2（`tools/usage-screenshots/`）は途中。別プロセスを起動してセカンドモニターで撮る所と、
  UIA要素の一覧（`-ListAnchors`）は実走済み。注釈の焼き込み（`Add-UsageShotAnnotations`）と切り抜きは
  書いただけで一度も走らせておらぬ。`shots.json`の`overview`は注釈が空のまま。
- 見本図面`demo.gcad`は要素のIdを固定してあり、キャンバス上の記号を`symbol-<Id>`で注釈の的に取れる。
- メニューを開いた姿・配置バー・貼り付けのゴースト・パーツエディタの絵は、キー送出や実マウスが要る。

- 撮影用スクリプトは実機確認スキルの`helpers.ps1`を使い回しておらぬ。あちらは対象を名前で探すため。
  自ら起動したプロセスのPIDだけを相手にし、終了は強制終了のみ（正規終了は殿のレイアウトを上書きする）。

### 本セッションで入った設計のうち、後で踏みやすい所

- 図面に埋め込まれたパーツ定義は、パーツエディタで保存した時に限り更新される
  （`MainWindowViewModel.SaveEditedPart`）。開いただけ・置いただけでは従来どおり上書きせぬ（T-151の原則）。
  同時に、役割の変更で機器表の種別が変わる場合は`Device.Class`も合わせる（旧い種別のままの機器のみ）。
- 範囲選択の起点は`SelectedCell`のsetterで畳む。`SelectRange`だけが起点を保ったままカーソルを動かす。
  貼り付け位置の確認は`ToolMode.Paste`。行の挿入を伴う貼り付けもUndo一回で戻る
  （既存の行操作コマンドは使わず`RowOps.InsertRow`を直に呼んでおる。行操作コマンド自体は今もUndo対象外）。
- 選択モードの素のクリックでもマウスキャプチャを取るようになった（範囲ドラッグのため）。
  マウスまわりの不具合が出たら、まずここを疑うこと。
- `PartRole.Other`を足した。`PartResolver.ComponentKind`のswitchへの追加漏れは実行時例外になるゆえ、
  役割を足す時は`PartResolverOtherRoleTests`の全役割を回すテストが網になる。
- リリースノートは`docs/release-notes.md`。版を出すたびに先頭へ節を足す。書き忘れはテストで落ちる
  （csprojの版数と同じ見出しが在ることを確かめる）。手順は`memory: ecad2_release_procedure`の1.5へ足した。
- タグの打ち先が版によって違う。v0.9.6までは版数を上げたコミット、v0.9.5の出し直しとv1.0は
  ビルド元（exeの`ProductVersion`に刻まれるコミット）。経緯は`docs/todo.md`のT-165・T-172節。
