# 原本GuiEcadとecad2のセル配置（主図面）比較調査

隠密（key=1785485896132）記す。2026-07-31。家老急ぎ采配より。**調査のみ・実装せぬ。**

## 結論（先に）

**主図面（ラダー図面本体）の座標変換――要素位置・グリッド線・配線とも、原本とecad2は式のレベルで完全に一致しており、相違は見当たらなかった。** 殿が指摘された相違は、**主図面の層ではなく、パーツエディタの層（隠密が別途`ecad2-t133-height-basis-rework-scope-onmitsu.md`で報告した「フレーム＝h セル vs 2h-1 セル」の相違）を指しておられる可能性が高い**と見立てる（推測、事実と分けて記す）。ただし主図面・パーツエディタのいずれの画面を殿がご覧になったかは断定できず、**実機での画面突合（忍者の領分）が要る**。

## DoD1〜3：式を並べて示す

| 対象 | 原本GuiEcad | ecad2 | 一致 |
|---|---|---|---|
| 行rの中心線Y座標 | `GridGeometry.cs:20` `YRow(row) => Margin + (row+0.5)*Cell` | `GridGeometry.cs:20` `YRow(row) => MarginMm + (row+0.5)*CellMm` | **完全一致（1文字違わず）** |
| 要素の描画位置 | `DiagramRenderer.cs:851` `PushTransform(X(lb), YRow(e.Pos.Row))` | `DiagramRenderer.cs:1033` `PushTransform(X(lb), YRow(e.Pos.Row))` | **完全一致** |
| 主図面グリッド線（横） | `DiagramRenderer.cs:417` `y = Margin + (rw+0.5)*Cell`（行中心） | `DiagramRenderer.cs:569` `y = MarginMm + (rw+0.5)*Cell`（行中心） | **完全一致** |
| グリッド既定表示 | `RenderOptions.ShowGrid`既定`false` | 同左 | **一致** |
| 縦コネクタ（配線）の端点Y | `YRow(c.TopRow)`/`YRow(c.BottomRow)`（`:400`等） | 同型（`YRow(top)`/`YRow(bot)`） | **一致** |

**すなわち「要素は行の中心線に乗り、グリッド線も同じ行中心に引かれ、横配線もその線上を通る」という殿の仰せの絵は、原本・ecad2のいずれでも同一の式で再現される。** 主図面に関する限り、両者に差は無い。

## DoD4：波及の見立て

**主図面層に相違が見当たらぬため、この層からの波及は無い。**

**ただし別調査（`ecad2-t133-height-basis-rework-scope-onmitsu.md`5節）で、パーツエディタの層に相違を確認済み**——原本の`PartEditorWindow.PartEditorWindow.xaml.cs:196,265`は「中心基準・高さ＝hセルちょうど」でフレームを描くが、ecad2の`PartShapeGeometry.FrameRect`は「中心基準・高さ＝2h-1セル」。**この相違は主図面ではなくパーツエディタ固有のものであり、家老が懸念された『別の座標系の混同』はまさにこの2層の違いを指しておられると見受ける。**

**殿がご覧になった画面がどちらの層か（主図面のスクリーンショットか、パーツエディタのスクリーンショットか）によって、次に確かめるべき先が変わる**——主図面なら本調査どおり相違なしゆえ他の観点（配線・接続点等）をさらに深掘る要があり、パーツエディタなら既報のH-2/H-3論点がそのまま該当する。**この切り分けは実機の絵を見なければ隠密には判じられぬ**——忍者による画面突合を具申する。
