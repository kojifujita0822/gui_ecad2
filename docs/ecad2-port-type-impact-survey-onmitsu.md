## 1. 型の波及 — **既存呼び出しは無改修で通り申す**

`PortDef` は **positional な `readonly record struct`**（`Element.cs:41`）——
```csharp
public readonly record struct PortDef(string Name, int RowOffset, int BoundaryOffset);
```

**既定値付きの第4パラメータを足せば、既存の3引数呼び出しはそのまま通り申す。**
**殿裁定(2)「既定値の自動判定は不要・殿が設定なさる」ゆえ、既定値を1つ決めれば足り申す**——好都合にござる。

### `new PortDef(...)` の全所在

**再現手段**＝`Grep "new PortDef\(" C:/ECAD2` → 27件／8ファイル（うちdocs 3ファイルは文書）

| 箇所 | 件数 | 備考 |
|---|---|---|
| `ElementCatalog.cs:38-52` | **5** | 組込み。Motor の U/V/W（`:42-44`）＋既定 L/R（`:51-52`） |
| `BasicPartTemplates.cs:40-51` | **2ヘルパ** | **`TwoPorts()` と `MotorPorts()` を16テンプレートが共有**（`:83, 102, 123…381`） |
| `PartEditorCanvas.cs:460` | **1** | エディタでの追加（`$"P{n}"` 自動採番） |
| テスト3ファイル | 11 | |

**→ 実装側で触るのは実質3箇所にござる。**

### 【留意】殿が種類を設定なさる際の勘所

**`BasicPartTemplates` の16テンプレートは `TwoPorts()`／`MotorPorts()` の2ヘルパを共有しており申す。**
**テンプレートごとに違う種類を設定なさるなら、ヘルパを分けるか引数を足す要がござる**——
**共有のままでは16件が一律に同じ種類になり申す。**

### `with` 式は自動継承 — **無改修**

`PartOptimizer.cs:56-58`（保存時クランプ）と `PartEditorCanvas.cs:474`（ドラッグ移動）はいずれも
`p with { RowOffset = ..., BoundaryOffset = ... }` の形にて、**新フィールドは自動的に保たれ申す。**

### 3極記号・モータ・一般接点への及び方

| 対象 | ポート | 種類の設定 |
|---|---|---|
| **3極記号3種** | **0個**（`ElementCatalog.cs:47-48`） | **不要**——影響なし |
| **モータ** | 3個（U/V/W） | 要 |
| **一般接点（既定）** | 2個（L/R） | 要 |

### 【設計論点】同一座標に異なる2種を置けるか

`HasDuplicatePorts`（`PartOptimizer.cs:72-81`）と `IndexOfPortAt`（`PartShapeGeometry.cs:116`）は
**座標のみで重複を判定しており、種類を見ており申さぬ。**
**→ 現状のままなら「同じ座標に赤と青を1つずつ」は保存時に拒否され申す。**
**これを許すか否かは、殿裁定(5)の接続方法設計と併せて判ずる筋にござる。**

## 2. 永続化 — **改修不要**

### `.gcadpart`（自作パーツ）＝**接続点は保存されており、自動シリアライズにござる**

`PartLibrarySerializer.cs:51-73` は `JsonSerializer.Serialize(part, JsonOptions.Default)` のみ——
**手書きのマッピングを持ち申さぬ。フィールドを足せば自動で載り申す。**

実ファイルの形（`GcadCompatibilityTests.cs:21-24`）——
```json
"ports": [
  { "name": "L", "rowOffset": 0, "boundaryOffset": 0 },
  { "name": "R", "rowOffset": 0, "boundaryOffset": 1 }
]
```

### `.gcad`（図面）＝**接続点を持ち申さぬ**

`ElementInstance` は `PartId` のみを持ち（`Element.cs:66-67`）、
**接続点はライブラリ側から解決され申す**（`PartResolver.cs:10-15`）。
**→ 図面ファイル側の改修は一切不要にござる。**

**なお `Document.Library`（`Document.cs:11-12`）という埋め込みの器は在り申すが、
`src` 配下に代入箇所が無く実質未使用**にて、`WhenWritingNull` ゆえ書き出されており申さぬ。

### 旧ファイルを開いたら何が起きるか

**落ち申さぬ。** `.gcadpart` には **SchemaVersion 検査が無く**（`PartLibrarySerializer.cs:64-65`、
「バージョンフィールドを持たない…非対称は意図的」）、**不一致で例外を投げるのは `.gcad` と `.gcadparts` のみ。**

**新フィールドが無い旧JSONは、既定値で読まれる見込みにござる**——
`JsonOptions.Default`（`JsonOptions.cs:9-20`）に `PropertyNameCaseInsensitive = true` があり、
**欠落フィールドはコンストラクタの既定引数で埋まる**筋。

**【隠密の留保】これは型の性質からの推論にて、実測しており申さぬ。**
**`CellHeight` の先例（`Element.cs:58-62` ＋回帰テスト `GcadCompatibilityTests.cs:118-143`）は
「プロパティ初期化子つきの通常プロパティ」にて、`PortDef` の positional record struct とは宣言形が違い申す。**
**実装時に1件テストを置いて確かめられたい**（殿裁定(4)で分岐は不要だが、**落ちぬことの確認は要る**）。

## 3. パーツエディタ

### 3-1. 接続点の描画 — **1箇所のみ**

`PartEditorCanvas.cs:694-701`
```csharp
var c = CellToLocalMm(_ports[i].BoundaryOffset, _ports[i].RowOffset);
bool selected = i == _selectedPortIndex;
renderer.FillCircle(c, _geo.CellMm * 0.14,
    selected ? new Color(255, 255, 69, 0) : new Color(255, 30, 144, 255));
```
**塗り分けは `FillCircle` の第3引数を変えるだけ**にて、`IRenderer` 側の改修は不要にござる。

**メイン図面側（`DiagramRenderer`）はパーツの接続点●を描いており申さぬ**
（`FillCircle` の使用は縦コネクタ分岐ドット `:552` と手動 `ConnectionDot` `:610` の2箇所のみ）。
**→ 図面キャンバス側の描画改修も不要。**

### 3-2.【最重要】殿裁定(3)「赤丸／青丸」と現在の色が衝突いたし申す

**現在の色は「種類」ではなく「選択状態」を表しており申す**——

| 状態 | 現在の色 |
|---|---|
| **選択中** | `(255, 255, 69, 0)` ＝ **OrangeRed（赤系）** |
| 非選択 | `(255, 30, 144, 255)` ＝ **DodgerBlue（青）** |

**すなわち、今は「赤＝選択中／青＝非選択」にござる。**
**ここへ「赤＝種類A／青＝種類B」を重ねれば、使い手は見分けが付き申さぬ**——
**選択中の青丸が赤く見え、種類Aの赤丸が常に選択中に見え申す。**

**【隠密の具申・事実と分けて】**取りうる筋は3つと見立て申す——

| 案 | 中身 |
|---|---|
| **(P-1)** | **選択の表現を色以外へ移す**（外周リング・サイズ・二重丸等）。**種類に赤青を明け渡す** |
| **(P-2)** | **種類を赤青以外で表す**（形＝丸と四角、塗り＝塗り潰しと中抜き等）。**殿裁定(3)の変更を要す** |
| **(P-3)** | **色相で種類、明度・彩度で選択**（濃い赤／薄い赤）。**判別が難しく、某は推し申さぬ** |

**(P-1) が筋と見立て申す**——**選択状態は「今どれを触っておるか」の一時的な表示にて、
形やリングでも十分伝わる。種類は部品の恒久的な属性ゆえ、色で常時見えるのが望ましい**と考えるゆえ。
**ただしこれは使い勝手の話にて、殿のご意向を仰ぐ筋にござる。**

### 3-3. 種類を選ばせるUIの置き場所 — **前例がござる**

**Row4 の「弧の縦半径」欄が、そのまま雛形になり申す**（`PartEditorDialog.xaml:104-109`）——
**「選択中の要素の属性を、選択に追従して出し入れする欄」**にて、目的が同じにござる。
表示切替は `UpdateShapeStatus()`（`PartEditorDialog.xaml.cs:182-198`）。

**しかも「接続点を選択中か」の判定経路は既に通っており申す**——
`:197` の `DeleteShapeButton.IsEnabled = ... || ShapeCanvas.SelectedPortIndex >= 0`。

**足す要があるもの**——
- **`SelectedPort` プロパティ1つ**（`SelectedArc`（`:174`）に相当するものが接続点には無い）
- Row4 へ ComboBox 1つ（**Role の ComboBox（`:22-32, 53-54`）が enum→日本語ラベルの前例**）
- 種類変更時の `PushUndo()`（**Undoは既に接続点を対象にしており申す**——`Snapshot`（`:563`）に `Ports` を含む）

## 6. 家老の判じかねられた一点 — **別々の箱が良いと見立て申す**

**殿裁定(4)（自作部品に「制御シート用」「主回路用」の設定を新設）と、
T-133殿裁定4（3極記号は主回路シート限定）が二重になる件にござる。**

**粒度が違うゆえ、同じ箱には入り申さぬ**——

| 属性 | 粒度 | 収まる先 |
|---|---|---|
| **接続点の種類** | **ポート単位**（1部品に複数） | **`PortDef`** |
| **シート種別の限定** | **部品単位**（1部品に1つ） | **`PartDefinition`** |

**しかも部品単位の属性を運ぶ器は既にござる**——
`PartEditorExternalState(int WidthCells, int HeightCells, PartRole Role)`（`PartEditorCanvas.cs:18`）。
**シート種別限定はここへ1つ足せば収まり申す。**

**一方、接続点種類は `PortDef` 自身に持たせるほかござらぬ**（ポートごとに違うゆえ）。

**→ 別々に作るのが自然にて、無理に同じ箱へ入れれば粒度が壊れ申す。**

**なお「二重になる」というご懸念については**——
**T-133殿裁定4は `ElementKind`（組込み種別）への制約、
殿裁定(4)は `PartDefinition`（自作部品）への制約**にて、**対象が違い申す。**
**組込みと自作で別々の仕組みになるのは、既に `CreatesComponent`・`Ports` が
`PartResolver` で二分岐しておるのと同じ形**ゆえ、**不自然ではござらぬ**と見立て申す。
