# T-068 増分0 PoC 操作感評価（隠密）

対象コミット：`91b179e`（`poc/t068-part-editor-poc/`）
設計書§7「検証手順」どおり、隠密が直接操作して定性判断を行った（忍者実機確認は設計書で不要と
明記済み）。実行方法は独自のUI Automation合成マウス操作スクリプト（`ecad2-ui-automation`スキルの
手法を対象プロセス`T068PartEditorPoc`向けに移植、scratchpad配下）を用いた。

## 結論：6論点すべてで「増分3本体実装に進めて問題ない」と判断

致命的な技術的障壁は見当たらない。侍が実装中に自己発見・修正したUndo/Redo単位設計のバグ
（README「重要な所見」参照）は実地検証で正しく機能することを確認した。ただし新規に軽微な所見を
2件発見、増分3実装時の修正対象として申し送る（下記参照）。

## 論点ごとの評価

### 論点1：描画基盤の応答性 — OK

線・矩形・円のpress→drag→release単純ドラッグ確定を実施。ドラッグした座標と生成されたプリミティブの
形状・位置が正確に対応し、視覚的にも直感的。`DrawingVisual`毎フレーム再構築方式でも操作上の遅延・
不整合は感じられなかった。

### 論点2：折れ線の作図操作 — OK

クリック4回で頂点追加→右クリックで確定を実施。作図中は青破線のゴムバンドプレビューが正しく追従し、
確定後は黒実線へ切り替わる。視覚的フィードバックが分かりやすく、誤操作（意図せぬ確定・頂点追加漏れ）
を誘発しない。GuiEcad原本の「右クリックのみ確定」（殿裁定=案A）は違和感なく機能する。

### 論点3：弧の作図とPartArcマッピング — OK

外接矩形ドラッグでの半楕円弧作図、選択後のステータスバー右側テキストボックスでの縦半径(Ry)事後調整
（`2.5`入力→Enter）とも直感的に機能した。Enter確定で即座に見た目（扁平だった弧がより丸みを帯びる）に
反映され、ドラッグ操作・数値調整いずれも意図と結果が一致する。

### 論点4：回転操作 — OK

矩形（`Rot`フィールド加算方式）・線（座標を直接回転して焼き込む方式）の両方を回転ドラッグで確認。
矩形は90度回転、線はほぼ垂直近くまで回転させたが、いずれも視覚的に自然で、GuiEcad原本の「型ごとに
異なる実装」をそのまま踏襲しても操作感に違和感は生じなかった。回転中心マーカー（十字）の表示も
分かりやすい。

### 論点5：Undo/Redo単位設計 — OK（基本機能）、軽微な所見1件

- 侍が実装完了後の自己レビューで発見・修正した「ドラッグ開始時点のスナップショットを積む」方式を
  実地検証：線の回転をUndo→回転前の斜め線へ正確に復元、Redo→回転後の状態へ正確に復元。矩形削除の
  Undo/Redoも同様に正確。**設計書の意図どおり機能している**。
- **新規の軽微な所見**：選択ツールで要素をクリックするだけ（実際にはドラッグ移動・回転させない）でも
  Undoスタックに1エントリ積まれてしまう（`BeginSelectOrMove`/`BeginRotate`が`CaptureMouse()`と同時に
  スナップショットを取り、`OnMouseLeftButtonUp`側の`CommitMove`/`CommitRotate`が実際の変化量を判定
  せず無条件で`PushUndoSnapshot`を呼ぶため）。GuiEcad原本は`_dragChanged`フラグで「実際に変化した
  場合のみ記録」する設計だが、本PoCにはこの判定が無い。実害は「クリックで選択しただけでUndoが1つ
  余分に積まれる」程度で軽微だが、増分3実装時は変化量ゼロ判定を追加することを推奨する。

### 論点6：座標変換・スナップ・ヒットテスト — OK（基本機能）、軽微な所見1件

- パン（中ボタンドラッグ）・選択ヒットテスト（線・矩形・円・弧いずれも正しく選択可能、ヒット
  許容誤差0.3セルも実用上妥当）とも正しく機能した。
- **新規の軽微な所見**：Ctrl+ホイールでのズームは実際の表示（拡大縮小）には正しく反映されるが、
  ステータスバーの「Zoom: X.XX」表示が更新されないまま`1.00`固定になる。コード確認により原因を
  特定済み——`PartEditorCanvas.Zoom`プロパティのsetter（`PartEditorCanvas.cs`）が`Notify()`
  （`StateChanged`イベント発火）ではなく`Draw()`のみを呼んでいるため、`MainWindow.UpdateStatus()`
  が起動されない。機能自体（ズーム）への影響はなく表示専用の実装漏れ。増分3実装時に修正対象と
  して申し送る。

## 完了判定（設計書§7準拠）

6論点すべて「増分3本体実装に進めて問題ない」水準に達している。発見した2件（Undo余剰積み・ズーム
表示未同期）はいずれも軽微でPoCの結論を左右しないが、増分3実装時に併せて修正することを推奨する。
