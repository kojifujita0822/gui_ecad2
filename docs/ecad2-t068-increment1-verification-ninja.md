## 検証観点（家老申し送り）

1. メニュー「パーツ(_P)」→「新規作成...」でダイアログが開き、名前・幅高さ・役割を入力して保存できること。名前未入力時はバリデーションで保存が拒否されること
2. 保存後、部品選択パネル（配置用）・「自作パーツ」サブメニュー双方に新規パーツが反映されること
3. 「自作パーツ」サブメニューから既存パーツの編集・削除ができること
4. テストモード中は「パーツ(_P)」メニュー配下（新規作成・自作パーツサブメニューとも）がグレーアウトし操作不能なこと

## 判定結果

- 名前「忍者テストパーツ01」・幅3・高さ2をValuePattern.SetValue（UIA非占有）で入力、保存自体は成功（部品選択パネルへの反映で確認、下記）
- **未確認**：役割（RoleCombo）の選択で`SelectionItemPattern`が「サポートされていないパターンです」という例外になり、意図した役割（コイル）を選択できないままOKが実行された。保存されたパーツの実際の役割値がコイルになっているかは未確認（推測報告禁止のため確度不明のまま報告）

### 観点2: 前半OK・後半は重大な疑いにより未確認

### 観点3: 未確認（観点2後半と同一の問題により）

## 重大な所見：「自作パーツ」サブメニューが一貫して開けない

以下6パターンの操作手法をすべて試したが、いずれも「自作パーツ(_C)」のサブメニュー（動的構築される
はずの編集/削除項目一覧）が展開されず、メニュー階層全体が閉じる、または何も起きないという同一の
結果になった。

1. `ExpandCollapsePattern.Expand()` → 例外「サポートされていないパターンです」（パターン自体が提供されていない）
2. `InvokePattern.Invoke()` → メニュー階層全体（トップレベルのみ残して）が閉じる
3. 物理クリック相当（`Set-Ecad2Foreground`経由の`Invoke-Ecad2ScreenClick`） → 同上
4. `SetForegroundWindow`を挟まない直接`mouse_event`クリック → 同上
5. マウスカーソル移動のみ（クリックなし、ホバー展開を期待） → 変化なし
6. キーボードナビゲーション（`Alt+P`→`↓`で「自作パーツ」へフォーカス→`→`または`Enter`） → サブメニューは開かず、`→`では次のトップレベルメニュー（ヘルプ）へ移動、`Enter`ではメニュー全体が閉じる

**手法3以降はUIA固有の操作ではなく、実際のマウスクリック・キー入力に近い経路であるにもかかわらず
同一の結果になった点が重要**。これはUIA操作特有の限界というより、実装側の挙動である疑いが濃厚。

一次ソース確認（`MainWindow.xaml`）：

```xml
<MenuItem x:Name="CustomPartsMenu" Header="自作パーツ(_C)" SubmenuOpened="CustomPartsMenu_SubmenuOpened"
          IsEnabled="{Binding CanEditDiagram}"/>
```

このMenuItemは子要素（`Items`）を一切持たない自己終了タグとして定義されている。WPFの`MenuItem`は
一般に「`HasItems`が偽の項目はサブメニューを持たない葉ノード（クリック可能項目）として扱われ、
`ExpandCollapsePattern`自体を提供しない」という実装（一般的なWPF標準動作、未確定）である疑いが
強く、`SubmenuOpened`イベントハンドラで実行時にItemsを動的追加する設計自体が、そもそも「サブメニュー
を開く」という判定条件（HasItems）を満たさないために発火しない可能性がある。ただし、これは一次
ソース理論からの推測であり、忍者は実装コードの深部（WPF内部実装）までは確認しておらず**断定は
しない**（推測報告禁止のため確度を明示）。

## 回帰確認

部品選択パネル自体の表示・スクロール・既存パーツ（a接点/b接点/コイル/サーマル/セレクトSW/
タイマ接点各種/端子台/表示灯/非常停止/OR系）一覧は正常表示、回帰なし。

## 総合判定・要判断

観点1（バリデーション）・観点4（テストモードガード）はOK。観点2前半（部品選択パネル反映）もOK。
**観点2後半・観点3（自作パーツサブメニュー経由の編集・削除）は、サブメニュー自体が開けないため
未検証**。これが実装バグなのかUIA操作固有の限界なのか、確度を持って判別できていない。

推奨：侍・隠密による一次ソース確認（WPF `MenuItem`の`HasItems`と`ExpandCollapsePattern`提供条件の
実装確認）、または診断ログ計装（`CustomPartsMenu_SubmenuOpened`が実際に呼ばれているかの入口ログ）
での切り分けを推奨する。あるいは殿の実操作（物理マウスクリック）での再確認も有効と考えられるが、
手法3・4（合成マウスイベント含む）で既に同一結果のため、UIA/合成操作固有の問題である可能性は
低いとみている（ただし確定ではない）。
