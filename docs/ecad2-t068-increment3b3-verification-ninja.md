## 試行錯誤の記録（重要）

観点1の編集経路検証で、「矩形を削除→円ツールでドラッグ→OK保存」の操作後、配置済みパーツの形状が完全に消える（母線のみ残る）という事象に遭遇した。以下の手順で切り分けた:

1. PrintWindow・CopyFromScreen両方で同一結果 → 撮影手法の限界ではない
2. グリッド表示トグル・ズーム操作でも再現 → 一時的な描画タイミング問題ではない
3. 選択ツールでクリックすると要素自体は選択でき、プロパティパネルに正しい種別名が表示された → 要素の存在・PartId解決自体は正常
4. アプリ再起動・ファイル再読込でも同じ結果 → ランタイムキャッシュの問題ではなく永続化データ自体の問題
5. 保存された`.gcadpart`ファイルを直接確認したところ`"primitives": []`（空）だった → 保存時点で形状データが空だったことが直接原因
6. 編集時のステータステキスト確認コードに`.Current.Name`とすべきところを`.Name`と誤記していたため、実際には図形数の確認ができておらず、円描画操作の成否を見落としていた
7. 改めて図形描画後のステータスを正しく確認したところ「図形: 0個」のまま（円が追加されていなかった）と判明
8. ドラッグ開始座標（ウィンドウ相対Y=100付近）がツールバー領域（Y=91〜118相当）に重なっていたためドラッグがキャンバスに届いていなかったと特定
9. キャンバス内の安全な座標（Y=260以降）で再試行したところ正常に円が描画され、保存後は配置済みパーツの見た目も正しく円に変化することを確認

**教訓**: 検証コード自体のプロパティアクセスミス（`.Name`と`.Current.Name`の取り違え）により、操作の成否確認が抜け落ち、「実装バグ」に見える誤った所見を一時的に生みかけた。UIA検証コードのステータス取得は必ず`.Current.Name`等の正しいプロパティを使うこと、座標指定はツールバー領域との重なりを避けキャンバス内の十分内側を使うことを、今後の自戒とする。

## 範囲外の気づき

- パーツ選択リスト（`PartSelectionList`）は自作パーツも含めた全件が仮想化されており、末尾の自作パーツを見るには`ScrollItemPattern.ScrollIntoView()`を繰り返し呼ぶ必要があった（1回では数件しか進まない）。既存教訓（部品選択リストはScrollItemPatternをサポート）に「繰り返し呼ぶ必要がある」という補足が追加できそうだが、観点外のため記録のみに留める。
- 要素配置の正しい操作順序は「先にキャンバスのセルを選択→その後パーツ選択リストの項目をクリック」だった（`PartSelectionItem_Clicked`が`TryPlaceElement`を呼ぶ設計のため、パーツクリック時点でセル未選択だとエラーメッセージが出て終わる）。忍者は逆順で一度失敗した。
