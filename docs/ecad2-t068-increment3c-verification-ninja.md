## 検証中の教訓・ヒヤリとした点

- **RadioButtonの切替失敗が繰り返し発生した**：UIA SelectionItemPattern・物理クリックいずれでも、直前の状態や操作タイミングによってはツール切替が反映されない事象に複数回遭遇した（今回は接続点↔選択の往復で顕著）。**ツール切替操作の直後は必ずステータステキストで実際に切り替わったか確認してから次の操作に進む**ことを徹底する必要がある。今回、この確認を怠って「接続点ツールのまま」と思い込んで操作を続け、結果的に無駄な往復が複数回発生した。
- **ウィンドウ相対座標のうちY=150程度までがヘッダー領域（プロパティ欄・ツールバー）に該当し、キャンバスに届かないことがある**。増分3-b2/3-b3では気づかなかったが、今回のように基準枠が小さい・上端付近を狙う操作では特に注意が要る。クリック前に基準枠の実際の画面位置をスクリーンショットで確認する一手間を惜しまないこと。
- ダイアログを閉じた後は`GetWindowRect`が`(0,0,0,0)`を返す（無効ハンドル）。前回のダイアログ位置を使い回さず、**新しいダイアログを開くたびに必ず`GetWindowRect`を呼び直す**こと（今回、位置確認を1回省略したことが座標ズレの疑いを生み、余計な切り分け作業が発生した）。

**【重大な追加所見】保存時クランプ(`ClampPortsToFrame`)が新たな重複生成経路になっている**——観点1の検証部品を保存した結果、`T068増分3c枠外検証部品.gcadpart`は以下の内容になった:
```
P1: rowOffset=0, boundaryOffset=1  (元cell(1,0))
P2: rowOffset=0, boundaryOffset=1  (元cell(1,2)、クランプでrow=2→0に変化)
```
両者とも`boundaryOffset`が同じだったため、高さクランプで`rowOffset`が同じ値(0)に収束し、**保存後に完全同一座標の重複ポートが生成された**。`ClampPortsToFrame`は`ReclampPorts`(revert済み旧実装)と同様に重複チェックを一切行わない実装であるため、家老が事前に懸念していた「枠を縮めるとポートが同じ位置へ寄り重複が生じる恐れ」がそのまま的中した形。

コメントに「範囲外の接続点をそのまま永続化すると誤結線を招くため保存時にクランプする」とあるが、**クランプ自体が別の形の誤結線(2端子の同一ノードへの短絡)を生みうる**。原本踏襲・仕様範囲内の挙動ではあるが、実害(誤結線)につながる可能性がある論点として家老へ報告。
