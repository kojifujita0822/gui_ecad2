# T-122 実機確認記録（忍者）

対象コミット: `2965fd4`（隠密静的レビュー: `docs/ecad2-t122-review-onmitsu.md`、指摘事項なし）

## 検証観点（家老申し送り）

1. フロート中・非ドラッグ時はオーバーレイが表示されないこと
2. ドラッグ開始で表示・ドッキングエリア外へのドラッグでは反応しないこと（オーバーレイのハイライト無し・そこへドロップしても再ドッキングしないこと）
3. 配置ツールバーのドッキングエリア内でのみ再ドッキングが成立すること

## 手順・操作手法

- 「表示(V)」メニュー→「配置ツールバーをフロート化(F)」をInvokePattern（UIA、非占有）で実行
- フロートウィンドウはEnumWindowsで検出（Handle、Title=''、AvalonDock標準タイトルバー付き）
- ドラッグ操作は`SetCursorPos`+`mouse_event`合成（Ecad2Native、Win32 API合成マウスイベント。
  殿の実際の手による操作ではない）。フロートウィンドウのタイトルバー（「配置ツール」テキスト部分）を
  起点に、40ステップ/40ms間隔、距離300px超で実施
- オーバーレイの状態確認はUIA探索（Name="ここへドラッグしてドッキング"）＋
  `Save-Ecad2Screenshot`（PrintWindow方式）の両方で実施

## 判定結果

### 観点1: OK
フロート化直後（非ドラッグ時）、UIA探索でオーバーレイ要素が見つからず（Collapsed想定通り）、
スクリーンショット目視でも点線枠は表示されていない。

### 観点2: OK
フロートウィンドウのタイトルバーをドラッグ開始した時点でオーバーレイが出現（UIA・スクショ両方で確認）。
表示範囲はMainToolBarペイン領域のみに限定されており（狭小化の設計通り）、そのままキャンバス上
（ドッキングエリア外）でドロップしても再ドッキングは成立せず、フロートウィンドウは維持された
（EnumWindowsで可視ウィンドウ2件のまま＝フロート継続を確認）。

付随所見：ドッキングエリア外へドロップした後もオーバーレイは表示されたままだった（消えなかった）。
一次ソース確認（`MainWindow.xaml.cs:370-394`）では、`WM_EXITSIZEMOVE`処理は
`dropZone.Contains(cursor.X, cursor.Y)`が偽の場合`return`で即抜け、`Visibility.Collapsed`への
代入（387行目）に到達しないコード構造だった。T-121の教訓（「フロート中は表示し続け、再ドッキング
成功時にのみ消す」設計、`docs-notes`記載の往復訂正）と整合するため、意図された設計とみられる
（バグと断定はしない）。

### 観点3: OK
フロートウィンドウをMainToolBarペイン領域内（オーバーレイ表示範囲内）へドラッグしてドロップしたところ、
EnumWindowsで可視ウィンドウがメインウィンドウ1件のみに戻り、再ドッキングが成立したことを確認。
スクリーンショットでも配置ツールバーが元のペインへタブ統合された様子を確認。

## 回帰確認

- PlacementToolBarのボタン操作（再ドッキング後の「a接点配置 (F5)」InvokePattern）は正常機能
  （ステータスバー「ツール: 要素配置」へ正しく変化）→ OK
- 新規作成・シート追加等の基本操作も正常機能 → OK

## 範囲外の重大な所見（要判断）

再ドッキング成立後、通常は非表示のはずのタブヘッダー（「基本機能」「配置ツール」の見出し行）が
UIA・スクリーンショット両方で表示されたまま残った（`docs/ecad2-t122-review-onmitsu.md`にも
引用されているコード内コメント「PlacementToolBarDockingManagerは常時2タブ(基本機能/配置ツール)
構成」という記述と符合する構造上のタブヘッダーが、通常は非表示化されているはずのもの）。

- フロート化前（起動直後〜フロート化直後）：タブヘッダー非表示（スクリーンショット確認済み）
- フロート化→（本検証の観点3の操作で）再ドッキング後：タブヘッダー表示（UIA・スクリーンショット
  両方で「基本機能」「配置ツール」のText要素・Bounds確認済み）

T-122のコミット差分自体（`MainWindow.xaml.cs`のWM_MOVING/WM_EXITSIZEMOVE/FindVisualChild関連の
み、+62/-1）にはタブヘッダーのVisibility制御に関わるコードは含まれていない。T-121で新設された
「メニュー経由フロート化→実際のドラッグによる再ドッキング」という往復操作自体が、AvalonDock標準の
`Dock()`呼び出し（`MainWindow.xaml.cs:393`、T-122以前から既存のコード）を経由して初めて顕在化した
可能性がある一次ソース状況証拠はあるが、原因の確定はしていない（推測報告禁止のため断定しない）。
T-121検証時にこの往復操作（フロート→実ドラッグでの再ドッキング）が実施されていたかは本記録の
範囲外につき不明。

## 総合判定

観点1〜3・回帰確認とも OK。範囲外の重大な所見1件（タブヘッダー復活）あり、家老の判断を仰ぐ。
