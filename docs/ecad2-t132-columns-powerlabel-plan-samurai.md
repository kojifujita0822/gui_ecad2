## 3. 実装の段取り（増分）

### 増分の切り方——「各増分が単独で検証可能か」で区切った

**区切りの基準＝その増分だけをコミットした状態で、(a) ビルドが通り (b) 既存機能が壊れず
(c) その増分の効果を測るテストが書けること。**

| 増分 | 単独で検証できるか | 何で測るか |
|---|---|---|
| **1**（範囲定数） | **できる**——定数を足すだけで呼び出し元が無くとも成立 | 定数値を固定するテスト |
| **2**（列の占有判定） | **できる**——`IsColumnOccupied` は純粋関数。**呼び出し元が無くとも単体で測れる** | 述語の単体テスト（境界値・真偽の両側） |
| **3**（ダイアログUI） | **できる**——ダイアログ単体で値の受け渡しと範囲検証を測れる。**この時点では `UpdateSheetSettingsCommand` が列数を受け取らぬゆえ、実際の反映は起きない**（意図的な中間状態） | ダイアログのプロパティ・検証のテスト |
| **4**（コマンド拡張） | **できる**——ここで初めて増分2の述語が呼ばれ、実際に列数が変わる | コマンドのテスト（**呼び出し側のテストを必ず置く**、下記） |

**【増分2と4を分ける理由】** `samurai.md`【MUST】＝**述語を切り出したら呼び出し側にもテストを置く**。
**述語の単体テストだけでは「ガードを実装したのに一度も呼ばれていない」状態を素通しする**（T-125増分αで実証済み）。
**増分2で述語を、増分4で繋ぎ込みを、それぞれ別に測る形にすれば、この穴が構造的に塞がる。**

**【増分3が「効果の出ない中間状態」になる点を明示しておく】** 増分3の時点でダイアログに列数欄は現れるが、
OK を押しても列数は変わらない（コマンドが受け取らないため）。**これは意図的である。**
**T-139増分1で「増分の切り方が招いた中間状態の破綻」（殿裁定で消える定めのテストへ暫定の期待値を入れる要が生じた）
という前例があるため、ここでは「中間状態で何が起きないか」を先に書いておく。**
**忍者の実機確認は増分4の後に一度行えば足りる**——増分3単独での実機確認は求めない。

### 増分2：列方向の占有判定を新設

`MainWindowViewModel` へ `IsColumnOccupied(Sheet, int column)` を追加。**行版 `IsRowOccupied`（`:2686`）と同型に置く。**

**§2 は案1で決着した**ため、見るのは4種：

```csharp
internal static bool IsColumnOccupied(Sheet sheet, int column)
    => sheet.Elements.Any(e => e.Pos.Column <= column && column < e.Pos.Column + e.CellWidth)
        || sheet.Connectors.Any(c => /* 列境界 c.Column が column..column+1 に掛かるか */)
        || sheet.WireBreaks.Any(w => /* 同上 */)
        || sheet.Frames.Any(f => f.TopLeft.Column <= column && column < f.TopLeft.Column + f.Width);
```

**【設計上の要注意点：境界と列は別物である】**
`Connectors.Column` と `WireBreaks.Boundary` は**列境界**（0.5 刻みを含む）であり、
`Elements.Pos.Column` は**列そのもの**である。**同じ `column` という引数で両者を判ずるには、
境界と列の対応を明示的に定める必要がある。**

- 列 `c` が占める境界の範囲は `[c, c+1]`
- 縦コネクタが境界 `b` に在るとき、それは列 `floor(b)` と `ceil(b)-1` のいずれか、または両方に掛かる

**この対応の定め方は実装時に隠密のテスト設計へ諮る。** 誤ると「境界ちょうどに置かれた縦コネクタが
判定から漏れる」型の穴が空く（`memory: feedback_geometric_transform_endpoint_oversight` と同型）。
