> 2026-07-27 忍者。家老采配「T-133 ecad2側 実機現況確認」を受けての実機検証。
> 殿ご下命＝**「gui-ecadからその他図形そのものが移植されていないことが発覚した。
> 『パーツ』→『その他図形』を作成して移植してほしい」**。
> 役割分担＝**原本GuiEcad側とコード側は隠密**、**ecad2の実機側は忍者**（T-131と同分担）。

殿の実操作は用いておらぬ。検証シート＝**制御回路シート**（新規1枚）。

## 1. 総括

**図面へ「その他図形」を直接配置する手段は、ecad2に存在せぬ。**
ただし**図形を描く仕組み自体は在る**——`PartEditorDialog`（自作パーツの形状編集、T-068増分3-c実装済み）が
**図形ツール9種を備えておる**。すなわち**「図形を描く器はあるが、図面へ直接置く導線が無い」**という形。

## 2. DoD別の判定

### DoD(1) 「パーツ」メニュー配下に何があるか——**2件のみ**

```
パーツ(P)
 ├ 新規作成(N)...      Enabled=True   → PartEditorDialog（自作パーツ新規作成）が開く
 └ 自作パーツ(C)       Enabled=True
     └ (なし)          Enabled=False  ← 自作パーツ0件ゆえのプレースホルダ
```

**「その他図形」に相当する項目は無い。** 殿ご下命の「『パーツ』→『その他図形』を作成」は、
**この2件の並びへ第3の項目を新設する**という読みになると見受けられる（**解釈は家老・殿に委ねる**）。

なお`(なし)`は、T-068増分1で**`HasItems=false`によりサブメニューが展開されぬ構造的欠陥**を避けるべく
静的に置かれたダミー子項目（`docs/todo.md` T-068節）。**本日も正しく展開でき、当時の対処が効いておる**。

### DoD(2) 図形系の配置手段——**全経路を尽くして不在**

家老の挙げた代表例（矩形・円・楕円・直線・文字・折れ線）に加え、**弧・多角形・寸法線・引出線**も
探したが、**経路1〜7のいずれにも該当項目は無い**。

**各経路の全量**（数え上げの根拠として残す）：

- **経路1＝配置ツールバー「配置ツール」16件**：選択ツール(Esc)／a接点(F5)／OR a接点(sF5)／b接点(F6)／
  OR b接点(sF6)／コイル(F7)／端子台(F8)／自由線 横(F9)／自由線 縦(sF9)／縦分岐線(sF9)／接続点(F10)／
  配線分断(F10)／グループ枠記入／自作パーツ(F11)／テストモード(Ctrl+T)
- **経路2＝「基本機能」9件**：新規作成／開く／上書き保存／元に戻す／やり直し／PDF出力／行を追加／
  行を削除／テストモード
- **経路3・4＝17件**：a接点／b接点／コイル／サーマル／セレクトSW／タイマ接点NC／タイマ接点NO／
  タイマ瞬時接点NC／タイマ瞬時接点NO／モータ／押釦NC／押釦NO／端子台／表示灯／非常停止／
  ORa接点／ORb接点
- **経路5＝メニュー27件**：ファイル6（新規／開く／上書き保存／名前を付けて保存／PDF出力／終了）、
  編集6（元に戻す／やり直し／切り取り／コピー／貼り付け／削除）、**図面2（ドキュメント情報／画像挿入）**、
  表示7（グリッド表示／ダークモード／パネルを自動的に隠す／配置ツールバーをフロート化／
  現在のレイアウトを既定として保存／保存したレイアウトに戻す／既定レイアウトに戻す）、
  ツール2（設計チェック実行／テストモード）、パーツ2、ヘルプ2（使い方／バージョン情報）
- **経路7＝右クリック3件**：行3の前に行を挿入／末尾に行を追加／行3を削除（**行操作のみ**）

**シート種別に依存せぬことも確認済み**——部品リストは主回路シート（T-131検証時）でも制御回路シート
（本検証）でも**同一の17件**であった。

### DoD(3) 既存機能との区別——**4つが紛らわしいが、いずれも「その他図形」ではない**

| 既存機能 | 実体 | 「その他図形」との違い |
|---|---|---|
| **自由線**（`FreeLine`、F9／Shift+F9） | **主回路シート専用**。制御回路シートでは`IsEnabled=False` | **結線のための線**であり作図用の直線ではない。向き（横・縦）が別ボタンに固定され、任意角度・任意始終点を引けぬ |
| **グループ枠**（`GroupFrame`、「グループ枠記入」） | ラベル付きの枠。要素のグルーピング用 | **矩形に最も近いが用途が異なる**。ラベル編集機能を持ち（T-125増分β-1の対象）、注釈用の自由な矩形ではない |
| **画像挿入**（図面(D)メニュー） | 外部画像ファイルの貼り付け | ベクター図形ではなくラスタ画像。作図はできぬ |
| **接続点**（`F10`） | ●印。結線の分岐点 | 円に見えるが結線要素 |

**そして最も紛らわしいのが下記**——

### 【最重要】パーツエディタには図形ツール9種が既に在る（が、図面へは置けぬ）

`パーツ(P)→新規作成(N)...`で開く**`自作パーツ新規作成`ダイアログ**（`PartEditorDialog`）に、
**RadioButton形式のツールが9種**、いずれも`Enabled=True`で実装されておる：

```
選択 / 線 / 折れ線 / 矩形 / 円 / 弧 / 回転 / 文字 / 接続点
```

併せて`UndoButton`／`RedoButton`／`DeleteShapeButton`／`ズームを戻す`、および
`StatusText`＝`図形: 0個 / 接続点: 0個 / 表示倍率: 1.00倍 / ツール: 選択 - Ctrl+ホイールで拡大縮小、
中ボタンのドラッグで移動` を備える。**T-068増分3-cで実装された形状編集キャンバス**にござる。

**ここが本件の肝**——**「図形を描く器」は既にあるが、それは「パーツの形状を定義する」ためのもので、
図面上に図形を直接置くものではない。**

> **間接経路の存在（家老・隠密への申し送り）**：理屈の上では、パーツエディタで**矩形だけ・文字だけの
> パーツを自作し、それを`自作パーツ (F11)`で図面へ配置する**ことで図形を置ける道理にござる。
> **ただしこれは「その他図形」機能ではなく、迂回であり**、
> (a) 図形1つごとにパーツを作り名前を付けて保存する手間が要る
> (b) 幅・高さがセル単位（1〜12）に制約される
> (c) 機器表に載る「役割(Role)」を持つ器である
> ——という点で用途が異なると見る。**この迂回で足りるか否かは殿の御判断を要すると存ずる**
> （**忍者の判断で実証まではしておらぬ。理屈上の指摘に留める**）。

## 3. 検証手順（再現可能な形で）

1. `Start-Ecad2App`（セカンダリモニタ、Left=1960）
2. `＋`→シート追加ダイアログで`ControlCircuitRadio`を`Select()`→OK（**制御回路シート**）
   - 裏付け＝作成後、自由線H/V・接続点が`IsEnabled=False`、縦分岐線・配線分断が`True`
     （**T-131の主回路シートとちょうど逆**。シート種別が効いておる証左）
3. メニュー7つを`ExpandCollapsePattern`で順に展開し`MenuItem`を`Descendants`で採取（サブメニュー含む）
4. ツールバーは**タブを切り替えて両方**採取（非選択タブはツリーから消えるため、スキル6.1節）。
   タブは`TabItem`の`Name`が`AvalonDock.Layout.LayoutAnchorable`で判別できぬゆえ、
   **子`Text`要素の文字列で同定**した
5. `自作パーツ (F11)`→`PartSelectionList`を`ScrollPattern`で0→20→40→60→80→100%まで送り重複除去
   （**初期表示は8件／`VerticalViewSize=35.3%`**——T-131と同値で再現）
6. `Send-Ecad2Keys "{ESC}"`→`Set-Ecad2Foreground`→`Invoke-Ecad2CanvasRightClick`でContextMenu採取
7. `パーツ(P)→新規作成(N)...`（展開とInvokeを**同一PowerShell呼び出し内**で完結、スキル6.1節）
   →`EnumWindows`で`自作パーツ新規作成`を検出→`Descendants` 44件を採取→`キャンセル`で閉じる

## 4. 範囲外として検出（自らタスク化はせぬ）

- **`(なし)`プレースホルダの見え方**——自作パーツが0件のとき、`パーツ(P)→自作パーツ(C)`を開くと
  `(なし)`というDisabled項目が1件出る。T-068増分1の構造的欠陥対処として**必要な実装**であり
  不具合ではないが、**「その他図形」を同じ階層へ足すなら並びの見え方に関わる**ゆえ記す
- **`図面(D)`メニューが2件と手薄**——ドキュメント情報／画像挿入のみ。**「その他図形」の置き場所として
  `パーツ(P)`と`図面(D)`のどちらが自然かは、UI/UXの分岐**と見る（**殿の御判断を要する筋**、
  `memory: feedback_route_design_decisions_to_user`）。殿ご下命は「『パーツ』→『その他図形』」と
  **明示されておる**ゆえ、それに従うのが筋と心得るが、**判断材料として現況を記しておく**

## 5. 不明点（推測で埋めておらぬ）

- **原本GuiEcadの「その他図形」が何を指すか**は本検証の範囲外（**隠密の調査で定まる**）。
  ゆえに本書は「ecad2に図形配置の導線が無い」ことを示すに留まり、
  **「移植すべき中身が何か」は述べておらぬ**
- **パーツエディタで矩形のみのパーツを作り図面へ置く迂回**が実際に成立するかは**実証しておらぬ**
  （理屈上の指摘）。必要なら追加検証いたす
- **`ThermalOverload`等、既存部品の図形的な流用**の可否は検討しておらぬ
