## 3. 【決着済み・2026-08-02 改訂】行削除で、高さ2の要素をどう扱うか

- **`DeleteRowAtCommand`（`:3628`）は占有拒否を持たぬ**——
  **殿裁定2026-07-11で「占有拒否を撤廃し、対象行の要素は `RowOps.DeleteRow` が要素ごと削除する」**と定まっておる

### 案

| 案 | 中身 | 長所 | 短所 |

## 4. テスト方針

### 4-0. 【最初に釘を刺す】**「高さ2」は3行を占める**

**殿裁定11＝H-2（中心基準3行）ゆえ `[r-1, r+1]`。**
**「高さ2＝2行」と思い込んで期待値を組めば、そこで狂う**（家老の申し送り、忍者の見立て 2026-07-28）。

> **【2026-08-02 訂正】占有の半径を出す式が T-139(C)裁定（殿裁定2026-07-31）で改まっておる。**
> **旧＝`rowSpan = h-1`／新＝`RowSpanOf(h) = Math.Max(0, h/2)`**（`Element.cs:114`、侍が直読で確認）。
> **本増分が扱う3極記号は高さ2ゆえ `RowSpanOf(2)=1` にて新旧一致——下表の数値はそのまま通る。**
> **されど式そのものは別物にて、h=3以降は食い違う**（`h/2` は整数除算ゆえ、奇数は一つ下の偶数へ潰れる）。
> **実装のコメント自身が「高さ1・2では新旧が同値。変わるのは高さ3以上のみ」と戒めており**、
> **高さ2だけを見て確かめても式の違いは現れぬ。**
> **ゆえに `[r-1, r+1]` を「`h-1` から出た値」として読んではならぬ**——**次に高さ3の記号を扱う者が、
> 同じ引き算で期待値を組んで狂う。** 詳細＝`docs/ecad2-t133-increment4-expected-values-ninja.md` 冒頭の追記節。
グリッド10行20列・高さ2・幅1のときの期待値は次のとおり——

| 何 | 期待 |
|---|---|
| 境界 | `Row-1 >= 0 && Row+1 < Rows` → **内部行にしか置けぬ**（**表示行1と最終行には置けぬ**） |
| 占有 | `[r-1,r+1]` 同士の交差 → **アンカーが2行以内なら衝突**（真上・真下も塞ぐ） |
| ヒットテスト | **アンカーの上下1行を叩いても拾える** |
| `Ctrl`+矢印の上下限 | **高さ1より1行ずつ狭い** |
