## 3. 【裁可を仰ぐ】行削除で、高さ2の要素をどう扱うか

### 事実

- **`DeleteRowAtCommand`（`:3536-3548`）は占有拒否を持たぬ**——
  **殿裁定2026-07-11で「占有拒否を撤廃し、対象行の要素は `RowOps.DeleteRow` が要素ごと削除する」**と定まっておる
- **`IsRowOccupied` による拒否が掛かるのは別の2経路のみ**＝
  **最終行削除**（`:3485`）と**行数変更**（`:3506`）
- **ゆえに `DeleteRow` は実際に到達する。** 高さ2の要素があるとき、
  **中心行以外（`r-1` / `r+1`）を削除すると、その要素は削除されず `-1` シフトされて残る**
  ——**画面上その行に描かれておるのに消えぬ**という食い違いが出る

### 案

| 案 | 中身 | 長所 | 短所 |
|---|---|---|---|
| **(D-1)【推奨】** | **占有範囲にかかれば削除**（`Pos.Row - span <= targetRow <= Pos.Row + span`） | **殿裁定「その行の要素は要素ごと削除」の趣旨に最も忠実**。使い手から見て「見えている物が消える」 | 中心行から1行離れた行を消しただけで要素が消える（が、それが占有の意味である） |
| (D-2) | 中心行一致のみ削除（現行のまま）＋残った要素をシフト | 変更が要らぬ | **見えている要素が消えぬ。** さらにグリッド行数が減るゆえ、**占有が範囲外へはみ出しうる** |
| (D-3) | `GroupFrame` に倣い「高さを縮める」 | 枠と同じ流儀 | **要素の高さは種別が決める固定値**ゆえ縮められぬ（`DefaultCellHeight`）。**採れぬ** |

**侍の推奨＝(D-1)。** ただし**使い手の目に見える挙動が変わる**ゆえ、一存では決めぬ。

**フォールバック条項**——**もし殿の御意が (D-2) であれば**、
**`IsRowOccupied` の高さ対応（(h)）だけを先に入れ、`DeleteRow`（(i)）は現行のまま据え置く**という切り分けも成り立つ
（最終行削除・行数変更の2経路は塞がり、任意行削除の食い違いのみ残る）。

### `IsRowOccupied`（(h)）の側は、案に依らず高さ対応が要る

**同じ関数の中で `Connectors` と `Frames` は範囲で見るのに、`Elements` だけが一致比較**（`:2675-2679`）。
**高さ2の要素の占有行が最終行にかかっておっても「空いている」と判じ、行を削除できてしまう**
——削除後、要素の占有がグリッド範囲外へはみ出す。**(h) は (D-1)/(D-2) いずれでも要る。**

## 4. テスト方針

### 4-0. 【最初に釘を刺す】**「高さ2」は3行を占める**

**殿裁定11＝H-2（中心基準3行）ゆえ `[r-1, r+1]`。**
**「高さ2＝2行」と思い込んで期待値を組めば、そこで狂う**（家老の申し送り、忍者の見立て 2026-07-28）。
グリッド10行20列・高さ2・幅1のときの期待値は次のとおり——

| 何 | 期待 |
|---|---|
| 境界 | `Row-1 >= 0 && Row+1 < Rows` → **内部行にしか置けぬ**（**表示行1と最終行には置けぬ**） |
| 占有 | `[r-1,r+1]` 同士の交差 → **アンカーが2行以内なら衝突**（真上・真下も塞ぐ） |
| ヒットテスト | **アンカーの上下1行を叩いても拾える** |
| `Ctrl`+矢印の上下限 | **高さ1より1行ずつ狭い** |

### 4-1. 事前適用する勘所（`samurai.md`「テスト入力の対称性・退化性チェック」）

- **グリッドは非対称に**（`Rows=5` / `Columns=10`）——増分3のテストと同じ器を使う。
  T-125増分α・T-134で**「非対称にしたゆえ何件検出できた」の数値実例が2例**出ておる
- **高さ1と高さ2を混ぜる**——高さ1どうしでは行判定が `[r,r]` に潰れ、誤りが見えぬ
- **上下の隣接行それぞれ**を測る——片側だけでは符号の取り違えが消える
- **範囲の「外側」を測る**——**本日、某は退化入力のテストで行0（内側）を測って検出力を失い、実測で露見させた**。
  **緩みは外側にしか現れぬ**

### 4-2. RED先行証明の段取り

**改変ごとに1回ずつ回さずともよい**（`samurai.md`、T-134で実証）——**テスト名で帰属が分かれるなら同時に測る**。
本増分では次のように分ける見込み：

| 同時に測れる群 | 単独で測る要があるもの |
|---|---|
| `Kind` 経路の高さ／`PartId` 経路の高さ／主回路拒否（テスト名が分かれる） | **行削除まわり（(h)(i)）**——同じ「行削除」のテストへ両方が効きうるゆえ |

**【必ず含める入力】「高さ2の要素の**真上**の行を削除する」経路**（家老の申し送り 2026-07-28）。
**忍者が実機側から「誰も測っておらぬ交差」として挙げた経路と、隠密が静的レビューで見つけた漏れ2件が、
独立に同じ領域を指しておる**——**采配される前にWチェックが成立した形**にて、
**危うさの見立てが二方向から揃うておる。**
