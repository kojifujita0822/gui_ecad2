## 0. 【最重要の前提】「高さ2」は2行ではなく**3行**を占める

殿裁定11＝**H-2（中心基準）**。占有範囲は `[r-(h-1), r+(h-1)]` ゆえ——

| 高さ h | `rowSpan = h-1` | 占有範囲 | **占有行数 = 2h-1** |
|---|---|---|---|
| 1 | 0 | `[r, r]` | **1行** |
| **2** | 1 | `[r-1, r+1]` | **3行** |
| **3** | 2 | `[r-2, r+2]` | **5行** |

**「高さ2＝2行」「高さ3＝3行」と思い込んで期待値を組めば、そこで狂う。**
**忍者は本日、誤った期待値（`devices`=1件、実体は0件）が正しい実測を疑わせる場面を実際に踏んだ**
——`memory: feedback_disclose_counting_unit`。**期待値の誤りは、実測を疑う方向へ人を誘う。**

## 1. 各式と、高さ別の数値（グリッド 10行20列・幅1のとき）

### 1-1. 境界 `IsWithinGridBounds`（`:2793`）

```
pos.Row - rowSpan >= 0 && pos.Row + rowSpan < Rows
&& pos.Column >= 0 && pos.Column + cellWidth - 1 < Columns
```

| 高さ | 置ける内部行 | **ステータスバー表示行**（内部+1） | 置けぬ行 |
|---|---|---|---|
| 1 | 0〜9 | **1〜10** | なし |
| **2** | 1〜8 | **2〜9** | **表示行1・行10** |
| **3** | 2〜7 | **3〜8** | **表示行1・2・9・10** |

**列は高さに依らず 0〜19**（幅1のとき）。

### 1-2. 占有 `IsOccupied`（`:2835`）——**置く側と既存側の両方が高さを持つ**

```
el.Pos.Row - elRowSpan <= bottom && top <= el.Pos.Row + elRowSpan   （行の区間交差）
&& el.Pos.Column <= right && left <= el.Pos.Column + el.CellWidth - 1
```

**衝突する条件＝アンカー行の差が `(h₁-1) + (h₂-1)` 以下**。

| 既存 → 置く | 衝突する行差 | **最短で置ける行差** |
|---|---|---|
| 高さ1 → 高さ1 | 0 | **1**（隣接行に置ける） |
| 高さ1 → 高さ2 | 0〜1 | **2** |
| **高さ2 → 高さ2** | 0〜2 | **3** |
| 高さ2 → 高さ3 | 0〜3 | **4** |

**すなわち高さ2の要素の真上・真下の行は塞がる。** 実機では**「1行あけただけでは置けず、2行あけて初めて置ける」**
という形で現れる筈（高さ2どうしなら3行差）。

### 1-3. ヒットテスト `HitTestElement`（`:2852`）

```
el.Pos.Row - elRowSpan <= pos.Row && pos.Row <= el.Pos.Row + elRowSpan
&& el.Pos.Column <= pos.Column && pos.Column <= el.Pos.Column + el.CellWidth - 1
```

| 高さ | 拾える行 |
|---|---|
| 1 | アンカー行のみ |
| **2** | **アンカーの上下1行も拾える（計3行）** |
| **3** | **上下2行も拾える（計5行）** |

**右クリックメニュー・テストモード左クリックの両方がこの述語を通る**ゆえ、
**「アンカーでない行を叩いてもメニューが出る／ONになる」**のが正。**出なければ回帰。**

### 1-4. 接続点と基準枠（P-148後、`PartShapeGeometry`）

| | 式 | 高さ1 | 高さ2 | 高さ3 |
|---|---|---|---|---|
| `ClampPort` の `rowLimit` | `±(h-1)` | 0 | ±1 | ±2 |
| **基準枠の行半径** | `±((h-1)+0.5)` | **±0.5** | **±1.5** | **±2.5** |

**枠の方が常に半セル広い**ゆえ、**丸められた整数の`rowOffset`は必ず枠の内側に落ちる**（本日実測済み）。

## 2. 増分3で「高さ1では変わらぬ」と確かめた6経路——**高さ2で測り直す**

**本日の検証は、いずれも高さ1に限った確認にすぎぬ。** 増分4で高さ2が置けるようになったら再度測る。

| # | 経路 | 高さ2での期待 |
|---|---|---|
| 1 | **配置** | **表示行2〜9でのみ成功**。表示行1・行10は拒否 |
| 2 | **占有拒否** | **真上・真下の行も「既に要素があります」**。高さ2どうしは3行差で初めて置ける |
| 3 | **`Ctrl`+矢印移動** | **表示行2で上端停止・表示行9で下端停止**（高さ1より1行ずつ狭い） |
| 4 | **右クリックメニュー** | **アンカーの上下1行を叩いても3項目が出る** |
| 5 | **テストモード左クリック** | **同上、上下1行でもON表示に変わる** |
| 6 | **ドラッグ移動** | 境界は(1)と同じ。**要素を先に選択してから送ること**（本日の躓き、スキル既載） |

## 3. 誰も測っておらぬ交差2件（家老が采配へ採用）

### 3-1. グループ枠と高さ2——**基準も行数も違う**

| | 基準 | 行数 | 占有判定 |
|---|---|---|---|
| **要素** | **中心**（`[r-(h-1), r+(h-1)]`） | **2h-1** | **対象**（重複を拒む） |
| **グループ枠** | **左上**（`IsFrameWithinGridBounds`、`:2803`） | **h** | **対象外**（重複を許す） |

**測ること**＝**高さ2の要素をグループ枠で囲んだとき、枠が要素の占有3行を覆えるか。**
**枠を高さ2で作れば2行しか覆えず、要素の上下がはみ出す筈**——**これが仕様か不備かは述べぬ（観測のみ）。**

### 3-2. 行削除と高さ2——**隠密の静的所見と同じ領域**

**隠密が`IsRowOccupied`・`RowOps.DeleteRow`で「`Pos.Row ==`の軸で漏れた箇所」を指摘**しており、
**忍者は実機側から独立に同じ領域を挙げた**（家老の言＝Wチェックが采配前に成立した形）。

**測ること**——
1. **高さ2の要素の「真上の行」を削除**する。アンカーだけを見る実装なら**要素が壊れる／消える／重なる**
2. **アンカー行そのものを削除**したらどうなるか
3. **要素をまたぐ行を削除**したとき、下の要素が繰り上がって**占有が衝突せぬか**

**判定は機器表の件数＋`DeviceNameBox`の値**（撮影に依らぬ機械判定）。
