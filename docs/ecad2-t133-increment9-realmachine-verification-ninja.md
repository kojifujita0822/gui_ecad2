対象コミット: `6455cc0`（掲出、案A）／`c06692e`（3極記号6項目「横→縦」並べ替え）。
隠密静的レビュー＝要修正なし（`docs/ecad2-t133-increment9-reorder-review-onmitsu.md`）。

## 操作手法

UI Automation（`Invoke-Ecad2Button`／`ExpandCollapsePattern.Expand()`／`InvokePattern.Invoke()`）。
家老指示により文言・順序はUIAでのテキスト採取を主とし、目視スクリーンショットは行っていない。

事前にシートが0枚だったため「＋」ボタン（`シート追加`ダイアログ、既定値のままOK）で1枚追加し、
ツールバー・パーツメニューを有効化した。

検体は殿環境の実在自作パーツ4件（`T136AFFANY`／`T136AFFCTRL`／`T136AFFMAIN`／`T136UIMAIN`、
いずれも既存・T-133過去増分の遺物）を流用し、`pinned-parts.json`（当初`[]`）へ実際にピン留め操作で
書き込ませて検証した。検証後、`pinned-parts.json`・`main-layout.xml`とも退避コピーから復元し
ハッシュ一致まで確認済み（後述）。

## 観点別 OK/NG

### 1. 掲出（自作図形をピン留めすると`OtherSymbolsMenu`末尾にセパレータ＋項目で出るか）— **OK**

`T136UIMAIN`を1件ピン留め後、メニュー末尾に`ControlType.Separator`＋`MenuItem Name='T136UIMAIN'`が
既存11項目に続いて出現。`pinned-parts.json`も`["8787c841edb642c4bdf0af20b952955b"]`へ正しく反映。

### 2. 0件の時（セパレータごと消えるか）— **OK**

- 検証開始時点（ピン留め0件）でメニューは既存11項目のみ、セパレータ・ピン留め項目とも無し
- ピン留め2件→1件→0件と解除していく過程でも、0件に達した瞬間にセパレータごと消滅することを実測
  （静的な初期状態だけでなく、動的な遷移でも確認済み）

### 3. 並び順 — **OK**

- 3極記号6項目（ブレーカ・電磁接触器主接点・サーマル(OL)2極）はいずれも「横→縦」の順で採取
- モータ2項目も「横→縦」（据え置き、既存どおり）
- 既存11項目のラベル・順序は一貫して不変（添字が壊れていないことを確認）
- ピン留め項目は**名前順**——`T136UIMAIN`を先にピン留めし後から`T136AFFANY`を追加ピン留めしても、
  メニュー上は`T136AFFANY`→`T136UIMAIN`の順（ピン留めした順ではなく名前順）で正しく表示

### 4. 登録・解除のトグル — **OK**

- 同一項目（`T136UIMAIN`）で、`その他図形にピン留め`→クリック→`その他図形のピン留めを解除`と
  ラベルが正しく切替わることを、解除操作の直前に文言採取して確認
- 解除操作で`pinned-parts.json`から該当IDが正しく除去され、メニューからも即座に消えることを確認
- 全件解除まで通しても異常なし
