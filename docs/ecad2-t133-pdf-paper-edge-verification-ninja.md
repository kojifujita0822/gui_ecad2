# T-133 用紙の物理端を越えた描画はPDFに出るか（忍者、2026-07-28）

> 家老采配（低優先の繋ぎ）。**隠密が「不明」と区切った一点**——「用紙の物理的な端を越えた描画は
> クリップとは別の話にて、PDFを生成して実測しておらぬ」（`docs/ecad2-t133-pdf-clipping-survey-onmitsu.md` 3節）
> ——を実測で埋めるもの。**スコープ＝実測のみ。対処は決めぬ。**

**操作手法**：UI Automation ＋ `Ecad2Native::Click`／`SetCursorPos`+`mouse_event`（**Win32合成マウス。
殿ご自身の手による操作ではない**）／PDFコンテンツストリームの直読（撮影に依らぬ機械判定）。

---

## 0. 結論

| 問い | 答え | 根拠の質 |
|---|---|---|
| **用紙端を越えた描画はPDFで切り詰められるか** | **切られぬ。座標はそのまま書き込まれる** | **実測**（コンテンツストリーム直読） |
| **紙に出るか** | **出ぬ**（MediaBox外は表示・印刷の対象外） | **PDF仕様に基づく帰結。画像としては未実測と区切る** |
| **縮小フィットが救ってくれるか** | **救わぬ。要素のはみ出しは縮小の判定に入らぬ** | **実測**（縮小が働かぬまま用紙外へ出た） |

## 1. 【自己訂正】列数の見立てを誤っていた

**当初「既定列数40ゆえ常に縮小フィットが働く（`scale≒0.534`）」と家老へ報じたが、誤りであった。**

| | 値 | 出典 |
|---|---|---|
| `GridSpec`の**クラス既定** | `Rows = 22, Columns = 40` | `Sheet.cs:38-39` |
| **シート追加時に実際に入る値** | **`Rows = 10, Columns = 20`** | `MainWindowViewModel.cs:3198`／`SheetNavigationViewModel.cs:152` |

**クラス既定だけを見て、生成箇所を当たらなんだのが誤りの因**にござる。
**正しくは`RightBusX(20) = 199.5mm ≤ 205mm` ゆえ `CalcPageScale` は 1.0 を返し、縮小は働かぬ。**

**この訂正で結論はむしろ明快になった**——**縮小が働かぬまま要素が用紙外へ出た**ゆえ、
**「要素のはみ出しは縮小の判定に入らぬ」が実証された形**にござる。

## 2. 実測（PDFコンテンツストリームの直読）

### 2-1. 検体と配置

**検体**＝`T133PDFEDGE.gcadpart`（幅1・高さ1、**x=0→31.125セル＝280.125mm の横線**を持つ自作パーツ）。
**3極記号はecad2に配置手段が無い**ゆえ、家老の助言どおり自作パーツで代えた。

| 機器名 | 配置列 | アンカーのワールドX | 線の範囲（ワールド） |
|---|---|---|---|
| X1 | 列0 | `X(0)=15mm` | 15 → 295.125mm |
| X2 | 列17 | `X(17)=168mm` | 168 → 448.125mm |

### 2-2. PDFの実データ

`C:\ECAD2\sample\t133edge.pdf`（400,408バイト、PDFsharp 6.2.4、全2ページ）。
**コンテンツは`FlateDecode`圧縮**ゆえ、PowerShellの`DeflateStream`（**zlibヘッダ2バイトを飛ばす**）で展開した。

```
/MediaBox[0 0 595.276 841.89]      ← ページ1＝A4縦 210×297mm
```

```
q  1 -0 -0 1 56.6929134 94.9606299 cm      ← X1（列0）
   0 651.9685 m   794.0551 651.9685 l   S
Q
q  1 -0 -0 1 490.3937008 171.496063 cm     ← X2（列17）
   0 498.8976 m   794.0551 498.8976 l   S
Q
```

**絶対座標へ直すと**——

| | 始点 | 終点 | **MediaBox幅 595.276pt との関係** |
|---|---|---|---|
| **X1** | 56.693pt＝**20.00mm** | 850.748pt＝**300.13mm** | **255.5pt はみ出す** |
| **X2** | 490.394pt＝**173.00mm** | 1284.449pt＝**453.13mm** | **689.2pt はみ出す** |

**すなわち用紙幅の2倍を超える座標が、切り詰められずそのまま書き込まれておる。**

### 2-3. 変換式も数値で確定した

母線の実測（`43.937pt`／`579.685pt`）から逆算すると——

```
x'(mm) = x + 5.0        ← 平行移動のみ。スケール項なし（pageScale = 1.0）
```

| 対象 | 理論値 | 実測値 | 差 |
|---|---|---|---|
| 左母線 `X(0)-BusPad = 10.5mm` | 15.5mm | 43.937pt = **15.500mm** | 0.000 |
| 右母線 `RightBusX(20) = 199.5mm` | 204.5mm | 579.685pt = **204.549mm** | 0.049 |
| X1 の線の終点 | 300.125mm | **300.13mm** | 0.005 |
| X2 の線の終点 | 453.125mm | **453.13mm** | 0.005 |

**理論と実測が0.05mm以内で一致**。**この一致をもって、上の座標が要素の描画であることを同定した。**

## 3. 対照（同一PDF内）

**用紙内に収まる描画は、いずれも正しくPDFへ出ておる**——
左右母線（43.9／579.7pt）・行番号1〜10・母線名`N24`/`P24`・表題欄の矩形群（311.8〜581.1pt）・
ページ番号`1 / 2`。**いずれもMediaBox（595.276pt）内。**

**すなわち「PDFそのものが壊れておる」のではなく、用紙外の座標だけが紙に載らぬ**という形にござる。

### 3-1.【未達】「同じ検体が用紙内に収まる姿」は撮れておらぬ

**家老のDoD「欠ける前の姿を先に押さえる（before/afterの両方を実際に見る）」は部分的に未達**にござる。
**当初は列0を before（用紙内）として設計したが、1節の誤り（縮小が働くという前提）ゆえ、
実際には列0の検体も用紙外へ出てしまった。**

**補うには**＝`T133PDFOVER.gcadpart`（10セル線）を列0に置けば `15→105mm`（変換後 `20→110mm`）で
**用紙内に完結する**。**1枚撮れば対照が揃うが、セッション終了により未実施。**

## 4. 範囲外として検出（自らタスク化はせぬ）

1. **`RequiredContentWidthForScale`（`DiagramRenderer.cs:207-217`）は要素の描画幅を一切見ておらぬ**
   ——右母線・行コメント・主回路のmm実座標のみ。**ゆえに記号がどれだけ右へはみ出しても縮小は発動せぬ。**
   隠密が「未確認」と区切った箇所（同調査書3-1節）を、一次ソースと実測の双方で埋めた形
2. **シート追加で作られるのは`Rows=10, Columns=20`**——`GridSpec`のクラス既定（22/40）とは異なる。
   **クラス既定を仕様と読むと誤る**
3. **PDF保存ダイアログの既定フォルダが`C:\ECAD2\sample`**（`.gitignore`済み・検証成果物の置き場ゆえ実害なし）

## 6. 手法の記録（次に同じことをする者へ）

**PDFコンテンツストリームの直読手順**（撮影に依らぬ機械判定）——

```powershell
$bytes = [System.IO.File]::ReadAllBytes($pdf)
$txt   = [System.Text.Encoding]::Latin1.GetString($bytes)
# /MediaBox[...] を正規表現で拾う
# 'stream\r\n' 〜 'endstream' の生バイトを取り出し、先頭2バイト(zlibヘッダ)を飛ばして
# System.IO.Compression.DeflateStream で展開する
```

**pt→mm は `/2.8346`**（`K = 72/25.4`）。**PDFのY軸は下から上**ゆえ、Y座標の突合では反転に注意。
**PrintWindow撮影がPDFプレビューの色を誤る問題（スキル6.3節）を丸ごと回避できる。**
