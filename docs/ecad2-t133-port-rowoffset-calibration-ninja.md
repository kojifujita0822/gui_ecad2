# T-133 接続点 rowOffset のずれ 較正実測（忍者、2026-07-28）

> 家老采配「T-133 実機側の未了1件」。前回の到達点＝**高さ3セルのパーツで枠中央をクリックしたら
> `rowOffset`が0でなく1。クリック位置未較正ゆえ断定せず**という留保を解くのが本検証の目的。
> **スコープ＝実機側のみ。** コード側（隠密担当）の結論には引きずられず、独立に数値を採った。

**操作手法**：`Ecad2Native::Click`（Win32合成マウスイベント＝`SetCursorPos`+`mouse_event`。
**殿ご自身の手による操作ではない**）／UI Automation（`SelectionItemPattern`・`ValuePattern`・
`ExpandCollapsePattern`・`InvokePattern`）／`PrintWindow`撮影＋画素走査。
検証シート＝制御回路シート（新規1枚）。

## 0. 結論

**ずれは実在する。** 高さ3セルのパーツで**基準枠の中央を叩いても`RowOffset`は0にならぬ**。

**真因は2つの座標系の食い違いにござる**——

| | 縦方向の規約 | セル座標での範囲（高さ3のとき） |
|---|---|---|
| **基準枠の描画** | **上端基準** | **cellY 0 〜 3** |
| **接続点の`RowOffset`** | **中心行=0の上下** | **cellY -2 〜 +2** |

**重なるのは cellY 0/1/2 の3点のみ。**
**枠の下1セル分には接続点を置けず、枠の外（上2セル分）には置ける。**

## 1. 較正（これが前回欠けていたもの）

**測り方**＝パーツエディタの基準枠（灰色破線）を`PrintWindow`画像の画素走査で直に測った。
線幅0.1mm＝0.38px と1画素に満たぬため、**灰色の絶対値ではなく背景との差分**で拾う
（初回は絶対値の閾値140〜215で走査して**一本も拾えなんだ**。差分方式へ改めて解決）。

| 項目 | 実測値 |
|---|---|
| ダイアログ矩形 | スクリーン `(2260,140)` 800x600（ウィンドウ1400x800・セカンダリ Left=1960） |
| 基準枠 上辺（cellY=0） | **ダイアログ相対 y=240** |
| 基準枠 左辺（cellX=0） | **ダイアログ相対 x=134** |
| **セルピッチ** | **縦横とも 34px**（高さ1で y240→274、高さ3で y240→342＝34×3） |
| 換算式 | **cellY = (y - 240) / 34** ／ **cellX = (x - 134) / 34** |

**理論値との突合**＝`Margin 30mm × (96/25.4) = 113.4px`。
実測との差は**縦 +126.6 ／ 横 +20.6**で、**`ecad2-ui-automation`スキル5節既載の較正値と一致**した
（T-068増分3-c当時の値が本日も生きておる）。**セルピッチ34pxも同スキル6.4節の値と一致**。

## 3. 合う条件の境界（家老DoD「数値で出せ」）

実測から導かれる式（**7点すべてがこれに乗った**）——

```
RowOffset = clamp( Round(cellY) , -(高さ-1) , +(高さ-1) )      ※Round は半整数で偶数側へ
```

**高さ3のときの境界を相対yで示す**（枠は y240〜342）：

| クリック相対y | cellY | `RowOffset` | 枠との関係 |
|---|---|---|---|
| 〜171 | 〜-2.03 | **-2** | 枠の外（上）・クランプ |
| 172 | -2 | **-2** | 枠の外（上） |
| 189〜222 | -1.5〜-0.5 | **-1** | 枠の外（上） |
| 223〜257 | -0.5〜0.5 | **0** | **240が枠の上辺** |
| 258〜290 | 0.53〜1.47 | **1** | 枠内 |
| **291** | **1.5** | **2** | **枠の中央（症状の位置）** |
| 292〜325 | 1.53〜2.5 | **2** | 枠内 |
| 326〜342 | 2.53〜3 | **2** | **枠の下1セルは死角**（クランプ） |

**半整数の丸め**＝0.5→**0**／1.5→**2**／2.5→**2**（実測#5・#1・#6）。
**「枠のどこを叩いても0にならぬ帯」が y258〜342 に広がっており、これは枠の高さの約6割にあたる。**

## 5. 家老の追加観点への回答＝**隅**にござる

**問い**＝接続点の円は「基準枠の左上隅・右上隅」か、「左辺の中点・右辺の中点」か。

**答え＝隅**（左上・右上）。**辺の中点ではない。** 数値は上表のとおり——
枠が `y240〜274 / x134〜168` に対し、接続点は **(134, 240)** と **(168, 240)**。

### 5-1. 原本データでも同じ（a接点）

**a接点をパーツエディタで開く導線は見当たらなんだ**（下記6-2）ゆえ、
**(a)高さ1の新規パーツでの同値実測**と**(b)`a接点.gcadpart`の直読**の二軸で代えた。

`マイドキュメント\Ecad2\図形\a接点.gcadpart`（`widthCells:1, heightCells:1`）——

```
ports      : L(rowOffset 0, boundaryOffset 0) / R(rowOffset 0, boundaryOffset 1)   → 枠の左上隅・右上隅
primitives : 4本の線の y は -0.317 〜 +0.317   → y=0 を中心に上下対称
```

**接続点は隅**。そして**図形は y=0 を中心に上下対称ゆえ、枠（cellY 0〜1）に対し上半分が枠外へ出る**。
**隠密の所見「図形と接続点は行中心基準、基準枠のみ上端基準」は、実機・原本データの双方で裏付いた。**

### 5-2. 家老が外された前提について

**「1/16刻みゆえ`0.9375`のような値で接続点を置けてしまう」が誤りであった件は、本実測とも符合する。**
**7点すべてが整数へ落ちており、非整数の`RowOffset`は一つも観測されなんだ**（JSONも整数のみ）。
