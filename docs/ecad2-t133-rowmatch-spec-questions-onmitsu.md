## 訂正1【最重い】DRCの「論点消失＝確定」は誤り——**自作パーツはDRCに載る**

**隠密は「高さ2になるのは4種のみ」と `ElementCatalog.DefaultCellHeight`（組込み種別の既定値）

**己が別系統と申したものを、DRCの判定では組込みの枠で数えた。**

**一次ソース**＝`PartResolver.cs:29-34`
```csharp

{

    if (part is not null) return part.Role != PartRole.NonSimulated;   // ← 自作パーツはここ
```

**ゆえに自作パーツは、Roleが接点・コイル等であれば `CreatesComponent = true` となりDRCに載り申す。**
（組込み15件のうち `NonSimulated` は三相モータ1件のみ＝`BasicPartTemplates.cs:249`。

# 【采配4追記】`NetlistBuilder` の4案評価 — 殿ご指摘「制御回路にも高さ2以上が置けてしまう」を受けて

## まず、隠密の前回報告に不正確がござった

**前回「横配線・右母線自動接続の対象から外れる」と報じたが、それだけではござらぬ。**
**「外れる」と「誤って繋がる」の2つが同時に起き申す。**

**機序**——`AddHorizontalWireUnions`（`:210-217`）は `byRow` の行で判定しながら、
**繋ぐノードは `leftNode[i]` / `rightNode[i]`＝ポートの実座標**にござる。

```csharp
// :212-213

    unions.Add((leftNode[idxs[0]], leftRail));   // ← 判定は row、繋ぐのは別行のノード
```
`leftNode[i]` は `Node(e.Pos.Row + pl.RowOffset, ...)`（`:157`）——**`RowOffset != 0` なら別行**。

| 症状 | 中身 |
|---|---|
| **(a) 外れる** | 要素は中心行にしか索引されぬゆえ、**上下行に他の要素があっても隣接判定されぬ** |
| **(b) 誤って繋がる** | **中心行の条件（分断・縦コネクタの有無）で判定しながら、実際には別行にあるポートを母線・隣接要素へ結ぶ** |

**(b) は前回報じておらなんだ。「対象から外れるだけ」より悪うござる。**

## (N-1) の規模 — **大。`NetlistBuilder` の配列構造そのものを変える要がござる**

**現状の構造は「1要素＝1行、その行で最左・最右ポートを1組持つ」を前提としており申す**——
```csharp
// :129-132  すべて elements.Count 長＝要素ごとに1組

// :148-154  最左・最右は「全ポートの中から」選ぶ＝行を区別しておらぬ
```

**`RowOffset` を正しく扱うには、索引の単位を「要素」から「(要素, 行)」へ変えねばなり申さぬ**
——**同じ要素が複数行に現れ、行ごとに最左・最右ポートが異なる**ゆえ。

**波及箇所（`NetlistBuilder.cs` 内）**

| # | 箇所 | 要る改修 |
|---|---|---|
| 1 | `BuildElementConnections`（`:128-171`） | **配列構造の変更**（`[i]` → 行ごと）。`pl`/`pr` を行ごとに選ぶ |
| 2 | `BuildRowIndex`（`:174-185`） | 索引の単位を (要素, 行) へ |
| 3 | `:40` の列ソート | 行ごとの並べ替えへ |
| 4 | `AddHorizontalWireUnions`（`:205-217`） | 行ごとの最左・最右を使う |
| 5 | `AddRightRailAutoConnections`（`:223-238`） | 同上 |

**ネットリストだけ変えれば電気と絵が食い違い申す。**

**→ 規模＝増分1つ分以上。しかも電気的接続の中核にて、回帰の危険が高うござる。**

### 隠密が加えた2案の狙い
