## 3.【DoD 2・本件の要】#1と#4は二重に積まれるか——**積まれる。かつ、より重い問題が別にある**

### 3-1. 一次ソースで確かめた流れ

```
PlaceElementAtSelectedCell（isOr=true）
  → Elements.Add ＋ MarkDirty                     :2931-2932
  → 候補0件なら終了 / 1件以上なら                  :2954
     _orJoinTargetDraft を立て Tool=ConfirmOrJoinTarget   :2958-2959
        ├─ Enter → ConfirmOrJoinTarget            :3063  → Connectors.Add ×1〜2 ＋ MarkDirty
        └─ Esc・別セルクリック等 → ClearOrJoinTargetDraftIfAny  :3087
             → 【要素配置そのものを取り消す】Elements.Remove ＋ 機器表から除去  :3090-3092
```

**すなわち配置と合流先確定は、使い手から見て1つの操作**にござる——
**配置しただけでは中間状態であり、Enterで完結するかEscで丸ごと消える。**

### 3-2. 素朴に両方へ積むと、二つの不都合が出る

| | 症状 |
|---|---|
| **(あ) 二重積み** | **Undo 1回目でコネクタだけ消え、要素は残る**（中間状態が復活する）。2回目でようやく要素が消える＝**1つの操作にUndo 2回** |
| **(い) 取消後の空振り** | Esc・別セルクリックで**要素は取り消されるのに、配置時に積んだスナップショットは残る**。**Undoを押しても何も変わらぬ1回**が生じる |

**(い)は#4を積むか否かに関わらず、#1を積んだ時点で必ず生じる**——**ここが本件で最も見落としやすい点**にござる。

### 3-3. 【重要】(い)の対処は P-144 の救済とトレードオフになる

`ClearOrJoinTargetDraftIfAny` の呼び出し元は**性質の異なる2種**にござる（doc コメント `:3085` で列挙）——

| 呼び出し元 | 使い手の意図 | あるべき扱い |
|---|---|---|
| `CancelOrJoinTarget`（**Esc**） | **明示的に取り消した** | 履歴に残らぬのが自然。**スナップショットを破棄すべき** |
| `SelectedCell` setter（**別セルクリック＝P-144**）・ツール切替・文書差し替え・`AppMode` setter | **取消を意図しておらぬ** | **Undoで回復できるべき**。**破棄してはならぬ** |

**すなわち「一律に破棄する」も「一律に残す」も誤りにござる。**
**一律に破棄すればP-144の救済（隠密・家老の見立て「#1を計装すれば回復不能は解消する」）が失われ、**
**一律に残せばEsc取消のたびに空振りUndoが溜まる。**

### 3-4. 案と推奨

| 案 | 中身 | 長所 | 短所 | 規模 |
|---|---|---|---|---|
| **(U-1)【推奨】** | #1のみ積む。#4では積まぬ。**Esc経由の取消時だけスナップショットを破棄**（`UndoManager` へ破棄APIを新設し、`CancelOrJoinTarget` から呼ぶ） | **(あ)(い)とも解消し、P-144の救済も両立する** | **`UndoManager`（T-051以来の基盤）に新APIが要る** | +12〜20行 |
| (U-2) | #1・#4とも積む | 実装が単純（各1行） | **(あ)が残る**＝中間状態が復活し、使い手には明確に不自然 | +2行 |
| (U-3) | #1のみ積む。破棄はせぬ | 実装が最も単純。**P-144は救える** | **(い)が残る**＝Esc取消後に空振りUndoが1回 | +1行 |

**侍の推奨＝(U-1)。** 理由——
- **Undoの正しさは基盤への信頼に直結する。空振りするUndoは「Undoが壊れておる」と受け取られる**
- **`UndoManager` への追加は破棄メソッド1つ（5〜8行）で済み、既存23箇所の挙動は一切変わらぬ**
  （新メソッドを呼ぶのは新設の1箇所のみ）
- **P-144の救済と両立できるのはこの案のみ**

**【留保】Redoスタックとの相互作用は3案とも同じ**——`RecordSnapshot` は `_redoStack.Clear()` する
（`UndoManager.cs:25`）ゆえ、**配置した時点でRedo履歴は消える**。破棄してもRedoは戻らぬ。
**この点で案による差は無い**（侍が一次ソースで確認）。
