## 2. 観点1＝コンボで主回路専用が灰になるか **→ OK**

**両シートで測った**（家老の采配は主回路シートのみであったが、**症状の射程は経路を数える**ため両方採った）。

### 属性（`IsEnabled`）——パレットとコンボが**完全一致**

| シート | パレット（`PartSelectionList`） | 配置バーのコンボ（`PlacementPartComboBox`） |
|---|---|---|
| **MAIN**（主回路） | 21件中 **`T136AFFCTRL` のみ False** | 21件中 **`T136AFFCTRL` のみ False** |
| **CTRL**（制御回路） | 21件中 **`T136AFFMAIN`・`T136UIMAIN` の2件が False** | 21件中 **同じ2件が False** |

**前セッションの非対称——「同じシートで、パレットは灰・コンボは黒」——は解消した。**

### 色（画素採取）——**パレットで黒と灰の差が数で出た**

制御回路シートでの実測（各ラベルの `Text` 矩形内、輝度230未満の画素を集計）：

| 検体 | `IsEnabled` | 最暗色 | 輝度 |
|---|---|---|---|
| `T136AFFANY` | True | **#000000** | 0 |
| `T136AFFCTRL` | True | **#000000** | 0 |
| `T136AFFMAIN` | **False** | **#6D6D6D** | 109 |
| `T136UIMAIN` | **False** | **#6D6D6D** | 109 |

**【コンボのドロップダウンは色を測れなんだ・その理由】**
**`PlacementPartComboBox` は幅40px、ドロップダウンのPopupは幅43px**にて、**項目に文字が無い**——
**`ListItem` の子は `Image`（14x14）1つのみ**で、部品名は表示されておらぬ（撮影して確認）。
**加えてT136系検体のアイコンは空白**（図形が枠外か極小と見られる）ゆえ、**アイコンの濃淡でも測れぬ。**
**ゆえにコンボ側は属性で判じ、色はパレット側で採った。**

## 3. 観点2＝上下キーで無効項目を飛ばすか **→ OK（双方向）**

制御回路シートで測るべきところ、**主回路シートで `T136AFFCTRL`（無効）を挟んで測った**。
コンボを閉じた状態で `SetFocus()` してからキーを送り、`SelectionPattern` で選択を読んだ。

```
start    : T136AFFANY   (index 15)
DOWN x1  : T136AFFMAIN  (index 17)  ← index 16 = T136AFFCTRL(無効) を飛ばした
DOWN x2  : T136UIMAIN   (index 18)
DOWN x3  : ORa接点      (index 19)
UP   x1  : T136UIMAIN
UP   x2  : T136AFFMAIN
UP   x3  : T136AFFANY   ← 戻りも同じく16を飛ばした
```

**下りも上りも無効項目を素通りする。** 侍の挙げた未検証点は、**WPF既定どおりの振る舞い**にござった。

## 4. 観点3＝配置バーを開いたままシートを切り替えた時の見え方

### まず前提が成り立たなんだ——**切り替えられぬ**

**配置バーが開いている間、シート切替の経路はUIツリー上すべて `IsEnabled=False`**（実測）——
`SheetNavList` とその項目2つ／メニュー7つ全部／`＋`・`－`・`名前変更`・`設定` の4ボタン／
ツールバー全ボタン／`CanvasArea`／`DeviceTableGrid`／`PartSelectionList`。
**有効なのは配置バーの中身とステータスバーのみ。**（既載の `IsMainContentEnabled` がメインコンテンツ全体の
`IsEnabled` を落とす仕組み。スキル6.2節）

**シート切替の経路は `SheetNavList` のクリック1本のみ**——`図面(D)`・`表示(V)`・`編集(E)` の全メニュー項目を
列挙したが、シート切替に当たる項目は無い。

### 見え方——**隠密の推測は半分当たり**

**選択中と非選択で見え方が分かれる**（画素採取。バー開／閉の対で採った）：

| シート項目 | バー開 | バー閉 |
|---|---|---|
| `CTRL`（**非選択**） | **#6D6D6D**（灰） | **#000000**（黒） |
| `MAIN`（**選択中**） | **#0078D7**（青帯） | **#0078D7**（青帯） |

- **非選択の項目は正しく灰になる**（隠密の推測とは異なる）
- **選択中の項目は青帯のまま、開閉で一切変わらぬ**——**「無効化された項目が選択されたまま残る見え方」という
  隠密の推測は、選択中のシートについては当たっておる**

**【某の目視は誤っておった】** スクリーンショットを目で見て「シートリストが灰に見えぬ」と判じたが、
**画素を採ると `CTRL` は確かに灰であった。** `memory: feedback_screenshot_visual_misjudgment_thin_lines`
がそのまま効いた形にござる。**画素で採ったゆえ誤報を免れた。**

**不具合と断ずるものではござらぬ**——切替自体が不能である以上、実害の経路が無い。**「どう見えるか」の採取まで。**

## 5. 観点4＝サイレント拒否は残っておるか **→ 到達経路が消えた（＝実機からは測れぬ）**

### 素朴なベースライン（先に取った）

**主回路シートで主回路専用の `T136AFFMAIN` を配置**——**機器表 0行 → 1行**（`BASE1`、種別＝リレー）。
**配置機能そのものは生きておる。** これが無ければ「拒まれた」と「壊れておる」を分けられぬ。

### 「置けぬ組合せ」を確定の段まで持ち込む経路を数え上げた

| # | 経路 | 結果 | 手法 |
|---|---|---|---|
| 1 | パレットの無効項目を叩く | **塞**——配置バーが開かず、ステータスバーにも何も出ぬ（無言） | 合成マウス |
| 2 | コンボで上下キー | **塞**——無効項目を飛ばす（3節） | 合成キー |
| 3 | コンボの無効項目を叩く | **塞**——選択は動かず（`T136AFFCTRL` のまま）、ドロップダウンも開いたまま | 合成マウス |
| 4 | 配置バーを開いたままシート切替 | **塞**——経路が `SheetNavList` 1本のみで、それが `IsEnabled=False`（4節） | 合成マウス／合成キー |
| 5 | **コピー＆貼り付け** | **測定不成立——打ち切り**（下記） | 合成キー／UIA Invoke |

**経路1〜4はすべて塞がっており、`ValidatePlacement` のサイレント拒否へ至る手立てが実機から見つからぬ。**
**これは「防御が消えた」ではなく「防御に届く前に止まるようになった」**——**経路2の修正の効果そのもの**にござる。

**【射程】** 数え上げたのは**某が見つけた5経路**にて、ファイル読込・Undo/Redo・移動（ドラッグ）等は測っておらぬ。
**`ValidatePlacement` が実装に残っておるか否かはコードの側の確認**（隠密の領分）にて、**実機からは言えぬ。**

### 経路5を打ち切った理由——**対照が取れなんだ**

主回路シートに置いた `BASE1`（主回路専用）をコピーし、制御回路シートへ貼ったところ**機器表は増えなんだ**
（1行のまま、無言）。**枷が効いたように見える。**

**されど素朴なベースラインを混ぜたところ、主回路シート（正しい組合せ）へ貼っても増えなんだ**——
**2手法（`Ctrl+V` ／ メニュー `編集(E)→貼り付け(P)`、いずれも `IsEnabled=True`）で同じ。**

**ゆえに「制御回路シートで拒まれた」とは言えぬ。** 貼り付けそのものが成っておらぬのか、
機器表が貼付では増えぬ仕様なのか、**分けられておらぬ。** `ninja.md` の打ち切り基準（2手法で症状不変・
対照で明暗が分かれず）に従い、ここで止めた。

**【次の一手の案】**（往復を短くするため添える）
- (a) **機器表でなくキャンバスの絵**で確かめる（結果側の別の指標。スキル6.8節）
- (b) **保存ファイルの中身**を見る（最も確か）
- (c) 侍に**貼付の実装が機器表へ反映するのか**を一次ソースで確かめてもらう

## 7. 手法の新知見（**落とし先＝`ecad2-ui-automation` スキル**）

1. **【最も効いた】`PartSelectionList` の項目ラベルは「最後の `Text`」にある**——
   `ListItem` の子は `Image` ＋ `Text`（空、またはカテゴリ名「自作」）＋ `Text`（部品名）の3つ。
   **`FindFirst` で最初の `Text` を採ると空文字を拾い、全項目が1件に潰れる**（実際そうなり、
   21件が「1件」と出た）。**`Name` プロパティ自体は `Ecad2.App.ViewModels.PartSelectionEntryViewModel`
   という型名**ゆえ使えぬ。
2. **モーダルダイアログもPowerShell呼び出しをまたぐと閉じる——しかも「OK相当の結果」が残る**。
   「シート追加」ダイアログを開いた呼び出しと、種別を選ぶ呼び出しを分けたところ、
   **次の呼び出しでは既に閉じており、かつ既定の種別（制御回路）でシートが1枚出来ておった。**
   **既載の「メニュー展開状態は呼び出しをまたぐと失われる」（6.1節）と同型だが、あちらは『閉じるだけ』、
   こちらは『閉じたうえで何かが起きる』**——**気づかねば検証の前提（シート種別）が狂う。**
   **対処＝「開く→設定→OK」を同一の呼び出しで完結させる。**
3. **配置バーは `TreeWalker` で親を辿ってはならぬ**——`PlacementDeviceNameBox` から親を2段辿ったところ
   **デスクトップ全体（3840x1080）に出て、他アプリまで列挙した。** 配置バーはメインウィンドウ直下の
   別レイヤーに在る。**`AutomationId` で直に引くこと**（`PlacementPartComboBox` ／ `SelectedPartNameText` ／
   `SelectedPartThumbnail` ／ `PlacementDeviceNameBox`）。
   **なお配置バーのOK・キャンセル・拡張表示の3ボタンは `AutomationId` を持たぬ**——
   `Name='OK'` は他にも在るゆえ、**矩形のYで絞る**（本日は Y≈321）。
4. **色を測ろうにも文字が無い場面がある**（2節）。**測る前に「測る対象が画面に在るか」を確かめること**——
   **属性は取れても、それが目に見える形で描かれておるとは限らぬ。**
5. **`ComboBox` の `Name` プロパティが選択中の項目名になる**（`PlacementPartComboBox` の `Name` が
   `T136AFFMAIN` 等）。`ValuePattern` は非対応ゆえ、**`Name` か `SelectionPattern.GetSelection()` で読む。**
6. **シート種別は後から変えられぬ**——「シート設定」ダイアログには行数・左右母線名しか無い。
   **種別は「シート追加」の時のみ。** 検体シートは作り直す要がある。
7. **部品選択リストの初期表示は 21件中 8件しか取れなんだ**（38.1%）。既載の罠（17件中6件＝35.3%）の
   **再現にござる。** 数え上げには必ずスクロールを要する。
