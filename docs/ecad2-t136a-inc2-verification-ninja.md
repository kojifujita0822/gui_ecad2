## 2. Undo/Redo — **不具合に非ず**（忍者は判別できず、侍の読解で決着）

**忍者の観測**＝UIA `SelectionItemPattern.Select()` でコンボを変えた後、
**Undoを押しても戻らず、Undoボタンは終始 `IsEnabled=False`**。

**されど断じ申さなんだ**——**対照が成立しなんだ**ゆえ。接続点を1つ足してUndoを試そうとしたが
**接続点が2個のまま増えず**、**Undoボタンが効くこと自体を確かめられなんだ**。
**「実装がUndo対象にしておらぬ」のか「UIAの`Select()`がハンドラを迂回した」のかを分けられ申さぬ**と
両論併記で報じ、`ninja.md`の基準（3手で打ち切り）に従って止めた。

**侍の読解による決着**＝`CaptureExternalState`は`PushUndo()`の中でのみ走り、
**`PushUndo()`が呼ばれるのはキャンバス上の操作のみ**（図形の追加・削除・移動・回転・接続点の追加削除・
弧の調整＝9箇所）。**コンボの`SelectionChanged`は拾っておらぬ。**
**ゆえに配置先を変えただけではUndoスタックが積まれぬ**——**Undoボタンが`IsEnabled=False`であったのは道理**にて、
**UIAの迂回ではなかった。**
**原本のコメントも意図を明記しており申す**（`PartEditorWindow.xaml.cs:795`）——
**サイズ・役割がスナップショットに入るのは「たたき台の読み込みがそれらを変えるから」**であり、
**入力欄の直接変更をUndo対象にする意図は原本に無い。**

**【教訓】**「実装がUndo対象にしておらぬ」は正しく、「不具合である」は誤りであった——
**両論併記に留めたゆえ、侍が正しい側を示せ申した。**

**【侍よりの申し送り＝次に同種の対照を取る折に】**
**接続点を足すより、図形（線）を1本引く方が確実**——**`AddPort`は基準枠の範囲へクランプされ、
同座標なら無視される**ゆえ、**接続点が増えなんだのはこれが因**と見える。
**線を引けばUndoが積まれ、そこで初めて「Undo機構自体は生きておる」ことが示せる。**

## 3. パレットの予防的無効化 — OK（**逆も揃うた**）

**判定は`ListItem`の`IsEnabled`**（全件をスクロールしながら段階的に採り、取り逃しの無きようにした）。

| 検体 | `sheetAffinity` | **制御回路シート** | **主回路シート** |
|---|---|---|---|
| `T136AFFANY` | any | True | True |
| `T136AFFCTRL` | controlOnly | **True** | **False** |
| `T136AFFMAIN` | mainCircuitOnly | **False** | **True** |
| **`T136UIMAIN`**（**UI経由で作成**） | mainCircuitOnly | **False** | **True** |
| `T133INC1H2`／`T133INC1H3`／`T133P148H3`／`T138SNAP` | **フィールド無し＝既定any** | True | True |

**三点、申し添える**
1. **素朴なベースラインが効いておる**——**`any`とフィールド無しの5件は両シートで`True`のまま**。
   **枷を持つ2種だけが左右で入れ替わる**ゆえ、**「Falseになったのは枷ゆえ」と言い切れる**
2. **`T136UIMAIN`（UI経由）が`T136AFFMAIN`（手書き）と一字一句同じ挙動**——
   **UIから設定した値と手書きの値が、パレットの側でも同一に扱われておる**
3. **シート種別の同定を毎回固定した**——主回路シート側では`接続点記入 (F10)`が`True`であることを
   確かめており、**「主回路のつもりが制御だった」取り違えは起きておらぬ**
