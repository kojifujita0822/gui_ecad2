## 2. 現状（一次ソースで確かめた）

| 項目 | 実際 | 出所 |
|---|---|---|
| パーツエディタの格子線 | **無い。基準枠の外形のみ** | `PartEditorCanvas.cs:673-677` |
| 基準枠の描画 | `FrameRect(w, h, cellMm)` → `X=0, Y=-((h-1)+0.5)*cell, W=w*cell, H=2*((h-1)+0.5)*cell` | `PartShapeGeometry.cs:89-100` |
| 枠の線 | **固定値の薄灰 `(180,180,180)`・太さ 0.1mm・破線**（テーマ非追従） | `PartEditorCanvas.cs:668` |
| 座標系 | セル単位。**列＝境界基準 `0〜w`／行＝中心基準（中心行が `y=0`）** | `PartShapeGeometry.cs:10`・`FrameRect` docコメント |
| セル→mm | `CellToLocalMm(x, y) = (x*CellMm, y*CellMm)`。外側にパン・ズーム、内側に余白の2段変換 | `PartEditorCanvas.cs:231, 665-666` |
| 1セル | `9.0mm`（余白 `30.0mm`） | `PartEditorCanvas.cs:35` |
| スナップ刻み | **1/16セル** | `PartShapeGeometry.cs:18` |
| 接続点の可動範囲 | 境界 `0〜w`（整数）／行 中心から上下 `h-1`（整数） | `PartShapeGeometry.ClampPort` |

**ゆえに、枠の中のマス目は次のとおりになる。**

| 高さ設定 h | 枠が覆う行 | 横の区切り線 | 縦の区切り線（幅 w） |
|---|---|---|---|
| 1 | 中心1行 | **2本**（上端・下端） | `w+1` 本 |
| 2 | 中心±1＝3行 | **4本** | `w+1` 本 |
| 3 | 中心±2＝5行 | **6本** | `w+1` 本 |

**横の区切り線は `2h` 本、囲まれるマスは `2h-1` 行**——**これが殿にご覧いただきたい数**にござる。

### 既存のグリッド描画（メイン図面側）との差

`DiagramRenderer.DrawGrid`（`:559-572`）は**横線を「行の中心」に引いておる**（縦線は列境界）。
**セルの境目ではない。** 行中心＝要素の中心・行番号と揃えるための意図的な設計にて、
コメントにも明記がある。**すなわちラダー側の格子は「マス目」ではない。**

**本タスクで「何セル分か数えられる絵」を作るなら、横線は行の境目へ引く要がある**——
**メイン図面と見え方が違ってよいか**が、下記 案C の論点にござる。

## 3. 見せ方の案

**軸は3つ**——(a) 線を何処に引くか (b) 何処まで描くか (c) どう見せるか。
下の3案は (a)(b) の主要な組合せにて、(c) は全案共通の小論点として §4 に別掲する。

### 案A — マス目・枠の中だけ（最小）

- **縦線**＝列境界 `x = 0, 1, ..., w`（`w+1` 本）
- **横線**＝行の境目 `y = -((h-1)+0.5) + k`（`k = 0..2h-1`、**`2h` 本**）
- **枠の内側のみ。** 枠の外へは1本も出さぬ

| 長 | 短 |
|---|---|
| **狙いに直答**——枠の中のマスが数えられる | **枠の外に描いた図形の位置合わせには効かぬ** |
| **線の本数が幅・高さで決まる**（最大 13＋24＝37本）。ズーム・パンに依らず一定 | 殿の御見立て「あればグリッドで調整できる」には半分しか応えぬ |
| **実装が最も軽い**（純粋関数が枠の寸法だけで閉じる） | |

### 案B — マス目・キャンバス全域（推奨）

- 線の意味は案Aと同じ。**同じ刻みのままキャンバスの見えている範囲へ延ばす**
- 枠の内外で濃さを変える手も採れる（下記 §4-3）

| 長 | 短 |
|---|---|
| 案Aの長所をすべて含む | **ズームアウトで線が増える**（ただし下記のとおり**最大でも200本弱**にて、際限は無い） |
| **枠の外へはみ出す図形にも効く**——T-133 §4-1 のとおり ELB のテストボタンは 0.55セル、Breaker3P の弧は 0.42セル 枠の外へ出る。**はみ出しは許容する方針ゆえ、外にも目盛りが要る** | **枠が線の海に埋もれる恐れ**（濃淡で階層をつけて避ける。要実機確認） |
| 殿の御見立て「あればグリッドで調整できる」に直に応える | 実装が案Aより一段重い（可視範囲の逆算が要る） |

### 案C — ラダー踏襲（横線＝行の中心）

- `DiagramRenderer.DrawGrid` と同じ意味の線を引く。**横線は行の中心（`2h-1` 本）、縦線は列境界**
- 描画範囲は枠内・全域いずれとも組める

| 長 | 短 |
|---|---|
| **メイン図面と見え方が揃う**——同じ格子の上で作図しておる感覚になる | **マス目にならぬ**。「枠の中が何セル分か」は線を数えれば分かるが、**囲まれた区画として見えぬ**ゆえ本タスクの狙いには一段遠い |
| **接続点の乗る行が線として直に見える**（接続点は行中心にしか置けぬ） | **接続点と線が重なる**——接続点は半径 0.14セルの塗り円ゆえ、線の上に乗ると見分けにくい恐れ |

### 侍の推奨＝**案B**

理由は2つにござる。
1. **本タスクの狙い（マスを数える）と、殿の副次の御期待（作図の調整）を両方満たす**のは案Bのみ
2. **案Aとの実装差は「可視範囲の逆算と本数の上限」だけ**にて、後から案A→案Bへ広げるより一度で済む

**ただし短所は実機で確かめねば分からぬ**——**枠が埋もれるか否かは、絵をご覧になって判ずるのが筋**。
**もし煩雑と映れば、案Aへ縮めるのは容易**（描画範囲を枠の寸法へ差し替えるのみ）。

## 4. 併せて諮るべき小論点（全案に共通）

### 4-1. 線の色と太さ

**侍の案＝`DrawingTheme.Get(StrokeRole.Grid)` をそのまま使う**（ライト＝灰 `210`／ダーク＝灰 `70`、太さ `0.10mm`）。

- **利＝テーマに追従する。** メイン図面の格子と同じ色ゆえ、目に馴染む
- **併せて階層が自然に出る**——枠は灰 `180`・破線、区切りは灰 `210`・実線にて、**枠の方が濃い＝主、区切りが従**
- **【範囲外の気づき】枠の色は固定値の直書きゆえテーマに追従しておらぬ**（`PartEditorCanvas.cs:668`）。
  **ダークモードでは背景 `(32,34,38)` に対し灰 `180` は明るく浮く。**
  本タスクの範囲外と心得るが、**区切り線をテーマ追従で入れると、枠だけが追従せぬ不揃いが目に立つ**恐れがある。
  **落とし先＝`docs/proposed.md`（別件として起票）。家老のご判断を仰ぐ**

### 4-2. 中心行を強調するか

**行 `y=0`** は「接続点の基準」かつ「図形の基準線」にて、**高さの意味を判ずる上での要**にござる。

- **強調する**＝中心基準であることが絵で伝わる。**殿が「名と実体」を判ずる材料が増える**
- **強調せぬ**＝線が1本減り、見た目が素直

**侍の見立て＝本タスクの狙い（高さの意味を判ずる）に照らせば、強調する方が材料になる。**
ただし**中心行はマスの境目ではなくマスの中を通る**ゆえ、**マス目の絵に線が1本余計に入る**。
**推すほどの確信は無い。殿のお好みで決まる類と心得る。**

### 4-3. 枠の内と外で濃さを変えるか（案B・案Cを採る場合のみ）

- 枠の外を一段薄くすれば、**枠の範囲が線の海の中でも際立つ**
- 均一にすれば実装は素直

**侍の案＝一段薄くする**（案Bの短所「枠が埋もれる」への手当てゆえ）。

### 4-4. 表示の入切を設けるか

**先例あり**——メイン図面側は T-056 で入切可能にし、**既定＝表示**（殿裁定2026-07-11、`LadderCanvas.cs:43-45`）。

- 設ければ、煩雑と感じた時に消せる。**規模は小**（ツールバーへチェックボックス1つ、`PartEditorDialog.xaml` の Row1）
- 設けねば常時表示。**本タスクの狙い（絵で判ずる）には常時表示で足りる**

**侍の見立て＝先例に倣い設けるのが筋**だが、**本タスクの狙いには無くとも足りる**ゆえ、**殿の御随意**。

### 4-5. 列方向の刻み

**1セル刻みのみで足りる**と見る。理由＝**接続点は整数境界にしか置けぬ**（`ClampPort` が整数へ丸める）ゆえ、
半セル・1/16セルの補助線は判断材料にならず、線が密になるだけにござる。
**スナップ刻み（1/16セル）を線で表すことは考えておらぬ**——**もし要るとの御沙汰あらば別途承る。**

### 設計方針

**座標算出は Core 層の純粋関数へ切り出す**——`FrameRect`／`ClampPort` と同じ形。
`samurai.md`「**『テストしにくい』は設計の匂い**」に従い、**View に埋めれば単体テスト不能**になるゆえ。

**案Bを採る場合の要注意点（実測を添えて記す）**
1. **可視範囲の逆算が要る**——`DipToCell` の逆算で、キャンバスの四隅がセル座標で何処かを求める
2. **本数は有界と分かった**——`Zoom` は `Math.Clamp(value, 0.2, 8.0)` で**下限 0.2 倍**
   （`PartEditorCanvas.cs:143`）。1セル＝9mm＝約34DIP ゆえ、**最も引いた状態でも 1セル＝約6.8DIP**。
   ダイアログの既定 800x600 なら**縦約119本・横約60本＝計180本弱**にて、**上限ガードは要らぬ見込み**
3. **線が詰まる度合いも同じ計算で押さえられる**——**最も引いて 6.8DIP 間隔**。
   **潰れて塊に見えるほどではないと見るが、これは机上の見立てにて実機で確かめる**

**1と3は案Aには生じぬ**（枠の寸法だけで閉じ、幅・高さとも上限12ゆえ本数が有界）。
**案Bを推しつつ、この差は隠さず申し上げる。**

## 6. テスト方針

**新規機能ゆえ RED先行証明【MUST】の対象外**（修正前のコードが存在せぬ）。
ただし`samurai.md`の作法に従い、**境界・退化の入力は壊す実測で検出力を確かめる**。

| 観点 | 入力 | 期待 |
|---|---|---|
| 横線の本数 | 高さ 1／2／3 | **2／4／6 本**（`2h`） |
| 横線の位置 | 高さ2 | `y = -1.5, -0.5, +0.5, +1.5`（セル単位） |
| 縦線の本数・位置 | 幅 3 | **4本**、`x = 0, 1, 2, 3` |
| 退化 | **高さ 0** | `FrameRect` の `Math.Max(0, h-1)` と揃え、**枠と同じ2本へ潰れる**こと |
| 上限 | **幅12・高さ12**（`HeightBox` が `Math.Clamp(..., 1, 12)` で許す上限） | 縦13本・横24本 |
| 枠との整合 | 任意の `w, h` | **端の線が `FrameRect` の4辺と一致する** |

**入力の選び方**——`samurai.md`「テスト入力の対称性・退化性チェック」に従い、
**幅と高さに別の値を採る**（例＝幅3・高さ2）。**正方形を避けるゆえ、行と列を取り違える改変が検出できる。**

**壊す実測で確かめる改変（案）**＝(1) 行と列の入替え (2) `2h` を `h` にする (3) 端の `+0.5` を落とす
(4) `Math.Max(0, ...)` を外す。**いずれも RED になることを実測し、テスト名ごとに結果を記す。**

## 8. 留保（射程を自ら区切る）

1. **「枠が線の海に埋もれるか」は絵を見るまで分からぬ。** 本書の案Bの短所は**机上の見立て**にて、
   実測ではない。**ダークモードでの見え方も同様**にござる
2. **本数・位置の数え（`2h` 本・`2h-1` 行）は、`FrameRect` と `ClampPort` の実装を読んで導いたもの**にて、
   **実機で数えたものではない**。**実装後、忍者の実機確認で突き合わせる要がある**
3. **初稿では案Bの短所を「線が際限なく増える」と書いたが、`Zoom` の下限 0.2 を読んで取り下げた**
   （`PartEditorCanvas.cs:143`）。**実測は「下限倍率」までにて、
   180本弱の線が実際にどう見えるかは測っておらぬ**——**本数の有界性と見やすさは別の主張**にござる
4. **本書は「高さの名と意味」を一切判じておらぬ。** T-133 §4-1 の (H-2)／(H-3) の再考は**殿が絵をご覧になった後**の話にて、
   本タスクの範囲外と心得る
