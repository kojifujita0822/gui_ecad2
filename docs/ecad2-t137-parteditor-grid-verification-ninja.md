## 2. 殿裁定4件

### (1) 案B＝キャンバス全域 — OK

**横線・縦線とも34px間隔でキャンバス全域に及ぶ**（幅1×高さ1、全域走査）。

- 横線＝`y=155,189,223,257,291,325,359,393,427,461,495,529` の**12本**（走査範囲 y120〜548 内）
- 縦線＝`x=32,66,100,134,168,202,…,746` の**22本**（走査範囲 x8〜792 内）

**枠の外にも同じピッチで続いており、枠の中だけの格子ではない。**

### (2) 中心行の強調はせぬ — OK

**高さ1・2・3のいずれでも `y=240`（中心行の中心）に線は無い。**
行プロファイルに一度も現れておらぬ。**横線は「行の境目」＝半整数にのみ入る**という実装
（`GridLineYs`）どおりにござる。

### (3) 表示の入切は設けぬ＝常時表示 — OK（**二軸で確かめた**）

| 軸 | 中身 | 結果 |
|---|---|---|
| **A. UI要素** | パーツエディタの全44要素を列挙、操作系17件を検分 | **CheckBox 0件。グリッド関連のトグルは無い** |
| **B. 既存トグルの影響** | メインの`表示(V)→グリッド表示(G)`を**OFF**にしてからパーツエディタを開き直す | **数値が一字一句同一**（y155/325=213、y189/223/257/291=232、y359以降=246） |

**軸Bを足した理由**——**「入切UIが無い」だけでは、既存の類似トグルが誤って効いてしまう筋を潰せぬ。**
**実際に消えぬことまで確かめて初めて「常時表示」が言える。**
（確認後、グリッド表示は**ONへ戻し済み**＝起動時の状態）

### (4) 枠の外は一段薄く — OK

**同一の線の「枠の内」と「枠の外」を測った**——**別の線同士を比べておらぬ**
（`memory: ecad2_comparison_target_identity_pitfall`）。幅2×高さ2、枠は`x134〜202 / y189〜291`。

| 測った対象 | 範囲 | 支配色 | 背景255との差 |
|---|---|---|---|
| **縦線 x=168 の枠内**（y200〜280） | 81px | **232** | **23** |
| **縦線 x=168 の枠外**（y340〜420） | 81px | **246** | **9** |
| **横線 y=223 の枠内**（x140〜196） | 57px | **232** | **23** |
| **横線 y=223 の枠外**（x240〜266） | 27px | **246** | **9** |
| 背景（x240〜266, y240〜250） | 297px | 255 | 0 |

**同じ1本の線が、枠の内で232・外で246**。**背景からの隔たりで約2.6倍**にござる。

**理論値との突合**——実装は`outer = inner with { A = inner.A / 2 }`を全域に描き、
**枠の内だけ`inner`を重ねる二層**。線幅0.10mm＝0.378px（1画素に満たぬ）ゆえアンチエイリアスで薄まる。

| | 理論値 | **実測** | 差 |
|---|---|---|---|
| 枠外（outer単独） | 255-(255-210)×0.378×0.5 = **246.5** | **246** | 0.5 |
| 枠内（outerにinnerを重ねる） | 246.5-(246.5-210)×0.378 = **232.7** | **232** | 0.7 |

**両者が1以内で一致**。**「一段薄い」は実装の意図どおりに出ておる。**

## 3. 観点3-(b)＝ダークモードでの濃淡 — OK

背景`32,34,38`。**幅2×高さ3で、ライトと同じ物差しで採った。**

| 対象 | ライト（背景255） | ダーク（背景32,34,38） |
|---|---|---|
| 枠の破線 | **213**（差42） | **99,102,105**（差202） |
| 枠内の区切り線 | **232**（差23） | **50,54,59**（差59） |
| 枠外の区切り線 | **246**（差9） | **39,42,46**（差23） |
| **枠内÷枠外（差の比）** | **2.56** | **2.57** |

**濃淡の関係は両テーマで保たれておる**——比が2.56対2.57でほぼ同値。
**線の本数・位置もライトと同一**（枠内6本＝`2h`、内部4本、中心行に線なし）。

**理論値との突合（ダーク、Rチャンネル）**＝outer: `32+(70-32)×0.189 = 39.2` → 実測**39**／
inner: `39.2+(70-39.2)×0.378 = 50.8` → 実測**50**。**1以内で一致。**

## 4. 観点3-(a)＝枠が線に埋もれぬか — OK（ただし差はライトの方が小さい）

**枠の破線の方が区切り線より濃い**ゆえ、埋もれてはおらぬ。**ただし差はテーマで倍以上ちがう。**

| | 枠の破線 | 枠内の区切り線 | **差** |
|---|---|---|---|
| ライト | 213 | 232 | **19** |
| ダーク | 99,102,105 | 50,54,59 | **49**（Rチャンネル） |

**目視でも枠の輪郭は追える**（証跡2枚）。**ライトでは「枠の中だけマス目が濃い集まり」として認識される形**にて、
**破線そのものの輪郭はダークほど際立たぬ。** **数値としてはこの差19が最小の余裕**にござる。
**これが十分かは見せ方の判断ゆえ、忍者は数値のみを報ずる。**

## 5. 観点3-(c)＝最も引いた状態 — **潰れはせぬが、13本中8本しか背景と区別できぬ**

`Invoke-Ecad2CtrlScroll`で**表示倍率0.20倍（下限）**まで縮小した（ステータス表示で確認）。
**1セル＝34×0.2＝6.8px**——侍の見立てどおり。

**実測（幅2×高さ3、x300〜500、閾値を3まで下げて走査）**——

| 項目 | 実測 |
|---|---|
| 線の色 | **249〜252**（背景255との差＝**1チャンネルあたり3〜6**） |
| y200〜300（101px）に現れた横線 | **8本**（y=207,214,227,241,255,261,275,289） |
| その間隔 | **7, 13, 14, 14, 6, 14, 14**（px） |
| **6.8px間隔なら在るべき本数** | **13本**（間隔の和が12セル分ゆえ） |

**すなわち間隔が「1セル分（7px）」と「2セル分（13〜14px）」に割れており、
在るべき13本のうち5本が背景と区別できなんだ**——**閾値を3（1チャンネルあたり1）まで下げても、である。**

**線同士が重なって黒く潰れるのではない。逆に、薄まりすぎて一部が消え、間隔が不均等に見える**のが実体にござる。

**撮影手法の限界ではない**——**`CopyFromScreen`（実画面キャプチャ）でも
`PrintWindow`と寸分違わぬ結果**（同じy座標・同じ色249/252）を得た。スキル6.3節の作法に従い裏を取ってある。

**【ただし断定はせぬ】** **両手法とも「画面に出た画素」を採る点で同じ層**を見ており、
**盲点を共有しうる**（`memory: feedback_cross_check_shared_blindspot`）。
**加えてスキル6.3節は「微細なレンダリングパターンは静止画では視認の限界があり、人の目でしか
判別できぬ場合がある」と戒めておる。** **ゆえに「実用上どう見えるか」は殿の目視を仰ぎたい。**
**忍者が確たることとして報ずるのは上表の数値のみにござる。**
