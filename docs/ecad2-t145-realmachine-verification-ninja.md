# T-145（モータのデバイス名を大円中央へ寄せる） 実機確認（忍者）

対象コミット: 96544e4。隠密静的レビュー＝要修正なし（docs/ecad2-t145-motor-label-offset-review-onmitsu.md）。

## 操作手法

UI Automation（Invoke-Ecad2Button／ExpandCollapsePattern／InvokePattern）でシート追加・要素配置・
デバイス名入力までを行い、画素採取（PrintWindowスクリーンショット＋GetPixel走査）で中心ずれを実測した。
zoom350%、シート1に横向きモータ（デバイス名M1、行4/列5、PartId経路＝「三相モータ 横」）と
縦向きモータ（デバイス名M2、行6/列11、Kind経路＝「三相モータ 縦」）を1件ずつ配置して測定した。

## 測定方法

円の中心は、上端・下端の探索（狭い列帯での最初の暗画素検出、選択ハイライトの混入は非選択状態で撮影して回避）
と、複数行での左右対称点の中点（中心xの検算）を併用して求めた。縦向きモータは3本の結線が円の上端へ
収束する構図のため上端が結線と癒着し単純な上下端走査が使えず、円周上2点＋中心xから逆算する式
（cy = [dx(y)^2 + y^2 - botY^2] / [2*(y-botY)]）で中心yを求めた（複数行で計算し一致を確認、誤差1px未満）。

ラベルの位置は円内部（結線・円弧が入らない範囲）での暗画素のバウンディングボックス中心と、
濃淡重み付き重心の両方を採った。px/mm換算は理論値（96/25.4×3.5＝13.228px/mm）と、実測した円半径
（0.75セル＝6.75mmに対し実測約90.3～90.5px、13.38～13.41px/mm）の双方でほぼ一致した。

## 観点別 結果

### 1. 横向きモータ（M1、PartId経路） 中心ずれ実測

円中心 (654.5, 332.5)px。ラベル位置 バウンディングボックス中心 (653, 317.5)px、重心 (651.8, 317.1)px。
mm換算（px/mm=13.228）：
横方向 dx = -0.11～-0.20mm（ほぼ無視できる差）
縦方向 dy = -1.13～-1.16mm（ラベルが円中心より上に約1.1mm）

### 2. 縦向きモータ（M2、Kind経路） 中心ずれ実測

円中心 (654.5, 378.7)px。ラベル位置 バウンディングボックス中心 (655, 363.5)px、重心 (653.4, 363.8)px。
mm換算：
横方向 dx = -0.08～+0.04mm（ほぼ無視できる差）
縦方向 dy = -1.13～-1.15mm（ラベルが円中心より上に約1.1mm）

### 3. PartId経路とKind経路の比較

両経路とも縦方向のずれが約1.1mmでほぼ一致し、横方向のずれはいずれも0.2mm未満に収まった。
経路による差は無いと判ずる。

### 4. 回帰

M1・M2のいずれも配置・デバイス名設定・機器表反映（機器名種別欄にM1・M2がその他として表示）は
正常に動作した。他要素（a接点・コイル等）への影響は本ラウンドでは実測していない
（配置ツールバー・配置バーの動作自体はM1・M2の配置作業を通じて異常なく確認できている）。

### 5. 絵と名の食い違い

M1・M2とも、大円そのものの位置・寸法は理論値と整合する半径（実測約90.3～90.5px、
理論値6.75mm×px/mm比とほぼ一致）で描かれており、絵と名が別経路で食い違っている様子はない。

## 所見（数値の解釈）

殿・侍より示されたコイルの前例（理論値-5.5から実測補正-5.72、ずれ0.22mm）と比べると、
本節で実測したモータの縦方向ずれ（約1.1～1.15mm）はおよそ5倍の大きさで、コイルと同型・同値の
ずれとは言い難い。横方向のずれはコイル前例と同程度（0.2mm未満）に収まっており、横のみコイル型・
縦は別種のずれという形に見える。

コイルの前例はDefaultLabelDyの基準値をコイル自身の実測で補正済みの値（-5.72）である一方、
今回のDefaultLabelDy(Motor)は理論値のみ（侍の申告どおり）。同じ描画系（DrawElementLabelの
DrawText呼び出し）を通る以上、縦方向のずれの主因はフォント描画の基準点（アンカー座標を中心と
見なすか下端寄りと見なすか等）にあると推せるが、コイルの残差（0.22mm）とモータの残差（1.1mm）が
大きく異なる理由は忍者の手持ちの材料からは断定できぬ。断定は避け、実測値のみを報告する。
