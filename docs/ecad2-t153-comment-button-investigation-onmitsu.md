# T-153 着手前調査（隠密起草）——配置バーへの機器コメント入力と、機器名欄の明記

殿ご指摘二件——
1. 配置バーの左から二番目の小アイコン（`AutomationProperties.Name="(未定アイコン2)"`、
   `MainWindow.xaml:1946-1951`、吹き出し形グリフ）でコメント入力できぬか。**対象＝機器コメントで確定**（殿明言）
2. **「普通に入力すると機器名入力欄が出るが『機器名』と明記しないと混同しそう」**

家老の指示どおり、**二件を一括で**候補を組む。

---

## 0. 【重要】家老の見立てを二点、一次ソースで訂正する

### 0-1. 「既存の作法が無い」は誤り——ラベル付き入力欄の作法は既に確立しておる

家老は「`Watermark`／`PlaceholderText`／`Hint`の類は見当たらず、入力欄の直前にラベルの`TextBlock`を
置く例も`Views`配下には見当たらぬ」と述べられたが、**`MainWindow.xaml`本体に多数実在する**。

| 箇所 | 形 |
|---|---|
| `MainWindow.xaml:1617` | `<TextBlock Text="デバイス名:" .../>` ＋ 入力欄（プロパティパネル・縦積み） |
| `MainWindow.xaml:1627` | `<TextBlock Text="コメント:" .../>` ＋ `CommentBox`（同上） |
| `MainWindow.xaml:1532` | `<TextBlock Text="検索:" VerticalAlignment="Center" Margin="0,0,4,0"/>` ＋ 入力欄 |
| `MainWindow.xaml:1545` | `<TextBlock Text="置換後:" .../>` ＋ 入力欄 |
| `Views/PartEditorDialog.xaml:35,44,50,56,63` | 「名前:」「幅(セル、1〜12):」「役割:」「配置先:」等 |

**とりわけ`:1532`の検索パネルは、本件と同じ「横並びのラベル＋入力欄」**にて、
`VerticalAlignment="Center" Margin="0,0,4,0"`という寸法まで含めて**そのまま流用できる前例**にござる。

**`Watermark`等が無いのは家老の申されたとおり**——すなわち**ecad2の一貫した作法は「ラベルを置く」**
であり、透かし文字は一度も使われておらぬ。**新たに定める話ではなく、既にある作法へ揃える話**。

### 0-2. 語彙が既に食い違っておる——「デバイス名」と「機器名」

殿は**「機器名」**と仰せになったが、**現行の実装は一貫して「デバイス名」**を用いておる——
`PlacementDeviceNameBox`の`AutomationProperties.Name="デバイス名"`、プロパティパネルのラベルも
「デバイス名:」（`:1617`）。

**すなわちラベルを足す際、「機器名」と書くか「デバイス名」と書くかは、それ自体が分岐**にござる。
- **「デバイス名」で揃える**＝プロパティパネル・UIA名と一致し、実装の語彙とも揃う
- **「機器名」へ改める**＝殿の御言葉に従うが、**プロパティパネル側も併せて改めねば新たな不揃いを生む**
  （同じものが画面の二箇所で別の名で呼ばれる）

**隠密の所見**＝殿が「機器名」と仰せになった以上、**両方を「機器名」へ揃えるのが筋**と考える。
機器表（`DeviceTableGrid`）・DRC文言も「機器」を用いており（`機器 {name}: リレー接点が…`）、
**むしろ「デバイス名」の方が浮いておる**。ただしこれは語彙の統一という別軸の作業を伴うゆえ、
殿へ諮る要がある（3-3で案として立てる）。

## 1. 機器コメントの現況（一次ソース）

- **実体**＝`Device.Comment`。**機器（`Device`）単位**にて、同一デバイス名の全要素で共有
  （T-107殿裁定＝デバイス単位で共有、GX3準拠）
- **入力口**＝プロパティパネルの`CommentBox`（`MainWindow.xaml:1628`）→ `SelectedElementComment`
  （`MainWindowViewModel.cs:2281-2299`）
- **前提条件**＝getter/setterとも**要素がデバイス名を持ち、`Document.Devices.ByName`に登録済み**で
  なければ機能せぬ（`if (SelectedElement?.DeviceName is not string dn || dn.Length == 0) return;`）
- **表示**＝ラダー図上、機器シンボル直下に緑色

**原本GuiEcadとの対比**——原本（`MainPage.Properties.cs:432-463`）も**プロパティパネルのみ**が
入力口にて、配置時点の入力口は存在せぬ。**「配置と同時にコメントを入れる」はecad2独自の拡張**。

## 2. 配置バーから入力する道——現状は無いが、作れる

`PlacementOkButton_Click`（`MainWindow.xaml.cs:4265-4283`）の流れ——
`PlaceElementAtSelectedCell(partId, deviceName, isOr)` を呼び、その内部で**新規デバイス名の場合のみ**
`Document.Devices.ByName[deviceName] = new Device {...}` が走る（既存名なら上書きせず維持）。

**すなわちコメントを書き込めるのは、この登録の直後**。実装するなら同メソッドへ引数を1つ足し、
`deviceWasNewlyRegistered` のガード内で `dev.Comment = ...` を書く形になる。

**残る分岐点**＝**既存デバイス名を再利用した配置でコメント欄をどう扱うか**
——(i)欄を無効化 (ii)既存値を表示し上書き許可 (iii)常に上書き。**これも殿へ諮る筋**。

## 3. 【一括】候補——ラベルの明記とコメント欄を揃った形で

### 3-1. 幅の制約（先に確かめた）

配置バーは省スペースが眼目（殿注文＝小型横長化、T-033増分2）。現状の構成要素は
小アイコン2＋種別コンボ(40)＋サムネイル(24)＋部品名(min60)＋入力欄(220)＋OK(60)＋
キャンセル(76)＋拡張表示。**画面端クランプは`ClampToViewport`（`MainWindow.xaml.cs:4021`）が
既に効いており、`Measure`で実寸を測ってから位置を決める形**ゆえ、**幅が伸びても画面外へは出ぬ**
——**バーが画面内へ収まるよう位置が寄る**だけにござる。

**ただし「収まる」と「使いやすい」は別**——横に伸びれば伸びるほど、クリックした位置から
バーが遠ざかる。**殿ご裁定で「拡張表示ボタン・小アイコン1」が非表示化される分、幅に余裕が生まれる**
（侍へ采配済みとのこと）ゆえ、**その分をラベルとコメント欄へ充てられる**という見通しは立つ。

### 3-2. 候補三案（ラベル＋コメント欄を一体で組んだ形）

#### 案A＝両方ラベル付き・コメント欄は常時表示（最も素直）

```
[種別▼][絵][部品名]  機器名:[____220____]  コメント:[____160____]  [OK][キャンセル]
```
- **利**＝既存の作法（`:1532`検索パネル）そのまま。二つの欄が**同じ形式のラベル**を持ち、
  混同の余地が構造的に消える。殿ご指摘の両方に一度に答える
- **難**＝幅が最も伸びる（ラベル2つ＋欄1つ分）。非表示化で浮く分を充てても、なお現状より広くなる

#### 案B＝両方ラベル付き・コメント欄はボタンで開閉（隠密の推奨）

```
通常時: [吹][種別▼][絵][部品名]  機器名:[____220____]  [OK][キャンセル]
押下後: [吹][種別▼][絵][部品名]  機器名:[__160__]  コメント:[__160__]  [OK][キャンセル]
```
- **利**＝**コメントを使わぬ時は現状とほぼ同じ幅**に収まり、省スペースの眼目を守る。
  吹き出しボタンが**押した時だけ欄が現れる**という、グリフの意匠と挙動が一致する形。
  T-136(B)增分5の「選択に追従する出し入れ式ComboBox」と同じ流儀
- **難**＝開閉の状態が一つ増える。開いた時に幅が変わる（位置の再クランプが要る——
  ただし`PositionPlacementBar`が`Measure`から測り直す形ゆえ、開閉時に呼び直せば足りる見込み）

#### 案C＝ラベルは`ToolTip`のみ・コメント欄は常時表示（省スペース最優先）

```
[種別▼][絵][部品名]  [____220____]  [____160____]  [OK][キャンセル]
（各欄にToolTip「機器名」「コメント」）
```
- **利**＝幅の増加が欄1つ分のみで最小
- **難**＝**殿ご指摘の「明記しないと混同しそう」に答えておらぬ**——`ToolTip`は
  マウスを乗せねば見えず、キーボード操作では出ぬ。**キーボードファーストの理念とも噛み合わぬ**。
  **隠密は推さぬ**が、幅を最優先するならこの形もあり得るゆえ並べた

### 3-3. 併せて諮るべき二点

1. **語彙**＝「機器名」で統一するか（プロパティパネルの「デバイス名:」も改める）、
   現行の「デバイス名」で揃えるか（0-2参照）
2. **既存デバイス名を再利用した配置でのコメント欄の扱い**（2節末尾の(i)(ii)(iii)）

## 5. 侍への申し送り

- 案の選定・語彙・既存名再利用時の扱いの三点は殿の裁可を要する
- `PlaceElementAtSelectedCell`のシグネチャ変更は、着手前に呼び出し元を`grep`で洗われたい
- **UIA名を変える場合の影響＝隠密が確認済み。実質無し**——`ecad2-ui-automation`スキルを
  `デバイス名`で洗ったところ、ヒットは`:213`の**コメント中の注意書き1件のみ**

  ゆえに`AutomationProperties.Name`を「機器名」へ改めても既存の検証手順は壊れぬ。
  ただし忍者が手元で組む一時スクリプトまでは測っておらぬゆえ、実機に入る前に一声かけられたい
