# T-153 実現可否の調査（隠密）——配置バーのトグル方式（殿が形をお決めになった分）

## 殿の御言葉（家老経由）

> コメントボタンを押したらボタンをグレーアウトさせて新たに表示予定の「機器名」と「機器コメント」を
> トグルで表示させ、入力欄は同じものを使うのは可能か？

**結論を先に申す——可能にござる。しかも幅が一切増えぬ形にて、既存の構造とよく噛み合う。**
**ただし要となる論点が一つ在り、そこは殿の裁可を要すると存ずる（4節）。**

---

## 1. 実現できるか＝できる。道筋を示す

### 1-1. 必要なもの三つ（いずれも既存の型で足りる）

| 要素 | 形 | 前例 |
|---|---|---|
| ラベル | `<TextBlock x:Name="PlacementInputLabel" Text="機器名:" .../>` を入力欄の左へ | `MainWindow.xaml:1532`の検索パネル（横並びラベル）がそのまま流用可 |
| ボタンの押下表示 | `Button`→`ToggleButton`へ変え、`IsChecked`で押下状態を示す | 配置ツールバーのT-101（選択中ツールの恒久ハイライト）で確立済みの流儀 |
| 値の保持 | コードビハインドに文字列2つ（`_placementDeviceNameText`／`_placementCommentText`）を持ち、切替時に退避・復元 | 新規（下記2節） |

### 1-2. 「グレーアウト」の読み——家老の解釈でよいと存ずる

家老は**押下状態を示す意**（トグルが押されておる形）と読まれた。**隠密も同じ読みを採る**。
理由＝**無効化（`IsEnabled=false`）と読むと、押した後に元へ戻せなくなり「トグル」という
御言葉と噛み合わぬ**。押下状態の表示ならトグルとして往復でき、御言葉全体が整合する。

**なお`ToggleButton`の既定の押下表示は薄い**——現行の`Style="{x:Null}"`（WPF既定のまま）では
チェック状態の見え方が弱い恐れがある。**押下が判るだけの見た目にするなら、T-101で用いた
ハイライトの流儀へ揃えるのが筋**（実装時に侍が実機で確かめられたい）。

## 2. 切替時の値の保持——ここが要。されど解ける

**共用ゆえ、切り替えるたびに`TextBox.Text`を退避・復元せねば、打った値が消える。**

```
（概念。実装の形は侍の判断）
トグルON（機器名→コメントへ）:
  _deviceNameText = PlacementDeviceNameBox.Text;   // 退避
  PlacementDeviceNameBox.Text = _commentText;      // 復元
  PlacementInputLabel.Text = "機器コメント:";
トグルOFF（コメント→機器名へ）: 逆を行う
```

**確定時（`PlacementOkButton_Click`）は、今どちらを表示しておるかを見て「表示中の値」を
先に退避してから、両方を渡す**——**これを忘れると「コメントを打った直後にOKを押すと
コメントが落ちる」という穴が開く**（表示中の値がまだ変数へ移っておらぬゆえ）。
**実装時の最重要点にて、テストで必ず固定されたい。**

**開くたびの初期化**——現行`ShowPlacementBar`相当（`MainWindow.xaml.cs:3974`）が
`PlacementDeviceNameBox.Text = ""` としておる。**ここで変数2つとトグル状態も初期化する要がある**
（前回の配置で入れたコメントが次の配置へ持ち越されぬよう）。

## 3. 確定時の保存——要素が生まれた後に書ける。順序が定まっておる

`PlacementOkButton_Click`（`:4265-4283`）→`PlaceElementAtSelectedCell`の内部で、
**`deviceWasNewlyRegistered`の判定を経て`Document.Devices.ByName[deviceName] = new Device {...}`**
（`MainWindowViewModel.cs:3396-3398`）が走る。

**すなわち`Device`が生まれるのはこの一行**にて、**コメントを書けるのはその直後**。
`new Device { Name = ..., Class = ..., Comment = ... }` の形で**生成時に併せて入れるのが最も素直**
——既存の行へ1項目足すだけで済み、`dev.Comment = ...`を別に書く要すら無い。

**機器コメント（T-107）の器はそのまま**——`Device.Comment`という同じ場所へ入るゆえ、
プロパティパネル（`SelectedElementComment`）から見ても同じ値が見え、保存・描画も既存経路に乗る。

---

## 4. 【要・殿の裁可】既存デバイス名を再利用した配置でのコメントの扱い

**現行の`PlaceElementAtSelectedCell`は、既存デバイス名の場合`Device`を上書きせぬ**
（T-036の作法＝「既存デバイス名なら既存エントリを維持」）。

**すなわち「X001」という既存の機器名で配置し、コメント欄に何か打った場合——**
- **(i) 何もせぬ**（既存の`Device.Comment`を守る）＝現行の作法に忠実。**ただし打った値が黙って消える**
- **(ii) 上書きする**＝打った値が反映されるが、**同じ機器名を持つ他の要素のコメントも一斉に変わる**
  （`Device.Comment`は機器単位で共有ゆえ）
- **(iii) 既存値を欄へ出す**＝トグルでコメントへ切り替えた時、既に在る値を表示し、
  変えれば上書き・変えねばそのまま。**最も親切だが、「機器名を打ち終えるまで既存値が分からぬ」
  という順序の問題が残る**（機器名の入力途中で既存値を引くのは難しい）

**隠密の推奨＝(ii)上書き**。理由＝**使い手が欄へ打った以上、反映されぬのは驚きが大きい**。
**(i)は「打ったのに消える」という、本プロジェクトが繰り返し戒めてきた型**（書き込みが黙って
捨てられる＝`P-188`と同じ形）にござる。**ただし「他の要素のコメントも変わる」ことは
T-107の設計（機器単位で共有）そのものゆえ、驚きとまでは言えぬ。**

**これは殿の裁可を要すると存ずる。**

---

## 5. Undoの扱い——T-144の射程外にて、対象外が筋

**T-144は「パーツエディタの入力欄の変更をUndo対象に含める」**——あちらは
**`PartEditorDialog`の中で編集が進行し、ダイアログ内にUndo/Redoの仕組みが在る**ゆえの話。

**配置バーは性質が違う**——**OKを押すまで何も確定しておらぬ**。実際、
`PlaceElementAtSelectedCell`が`UndoManager.RecordSnapshot(Document)`を呼ぶのは
**配置が成立する瞬間ただ一度**（`:3376`）にて、**バー内の入力はUndoの単位に載っておらぬ**
（機器名を打っている最中にCtrl+Zを押しても、配置前の状態へ戻る類のことは起きぬ）。

**ゆえにトグルの切替・コメント欄への入力はUndo対象外が筋**にて、
**T-144との不整合は生じ申さぬ**。**確定後の`Device.Comment`は、配置のスナップショット一つに
含まれてまとめて戻る**——これが正しい粒度と存ずる（配置とコメントは使い手から見て一つの操作）。

## 6. 既存の機器コメント入力経路との関係——食い違わぬ

- **プロパティパネル**（`CommentBox`→`SelectedElementComment`、`MainWindowViewModel.cs:2281-2299`）＝
  **配置済みの要素を選んでから編集する経路**。同じ`Device.Comment`を読み書きする
- **配置バー（本件）**＝**配置と同時に初期値を与える経路**

**両者は同じ器を触るが、時点が違う**——衝突は起き申さぬ。**むしろプロパティパネル側の
ラベルが既に「コメント:」であるゆえ、配置バー側を「機器コメント:」とすると
語が揃わぬ**——**どちらかへ寄せるのが筋**（0節で申した語彙の統一と同根）。

**なお殿は「機器コメント」と仰せになった**ゆえ、**プロパティパネル側を「機器コメント:」へ
揃えるのが素直**と存ずる（併せて「デバイス名:」も「機器名:」へ）。

## 8. 侍への申し送り

1. **2節の「確定時に表示中の値を先に退避する」が最重要**——ここを落とすと、
   コメントを打った直後のOKで値が落ちる。**テストで必ず固定されたい**
2. **4節（既存デバイス名再利用時）は殿の裁可待ち**——実装前に確かめられたい
3. `ToggleButton`の押下表示が薄い恐れ（1-2）——実機で見え方を確かめ、
   弱ければT-101の流儀へ揃える
4. **UIA名を「機器名」へ改める場合の影響＝実質無し**（`ecad2-ui-automation`スキルを
   `デバイス名`で洗い、UIA名として引く箇所0件・コメント中の言及1件のみ）。
   ただし忍者が手元で組む一時スクリプトまでは測っておらぬゆえ、実機の前に一声かけられたい
