# nl-to-ladder-poc

殿ご提案（2026-09-14）「AIに口頭で動作を説明してシーケンス図面にする」の実現可能性検証PoC。
案1（2段階変換方式）——自然言語からは論理構造の判定とパラメータ抽出のみを行わせ、座標・結線の
レイアウト計算は決定的なコードで行う——のうち、コード側（中間表現→.gcad変換）を実証する。

自然言語の解析は本PoCの範囲外（殿ご裁可2026-09-14＝まずは決め打ちパターンで実証）。
`NlToLadderPoc/SelfHoldParser.cs`は「XXでON、YYでOFF、ZZ保持」という固定文型のみを正規表現で
解析するスタブ。将来この部分をLLM呼び出しへ差し替える想定。

## 使い方

```
cd NlToLadderPoc
dotnet run -- "PB1でON、PB2でOFF、CR1保持" out.gcad
```

`out.gcad`はEcad2.Appでそのまま開ける。

## 実証結果（2026-09-14、実機確認済み）

- 生成した`.gcad`をEcad2.Appで開き、自己保持回路として正しく描画されることを確認
- 設計チェック（DRC）で異常なし
- テストモードで実際にPB1押下→CR1自己保持→PB2押下→CR1解除、という電気的に正しい動作を確認

## つまずいた点と学び

自己保持接点（CR1のa接点、行1）を配置する際、当初はPB1（行0）と並列にするため左右両方の列境界に
`VerticalConnector`を置いたが、これは誤りだった。`NetlistBuilder.LeftRailReached`は「行の最初の
要素の左端より左側に縦コネクタ（分岐源）があれば、その行は左母線から遮断される」という設計のため、
自己保持接点の左端に縦コネクタを置くと、行1自体が母線から切り離されてしまう
（`DRC-LOAD-001`＝負荷CR1が左母線へ到達不可、として顕在化した）。

正しい配置は、自己保持接点の**右端だけ**を縦コネクタで行0の接続点へ繋ぎ、左端は行1自身の
母線直結に任せる形。この知見は、将来の本実装（中間表現→レイアウト変換ロジック）でも
そのまま使える定石として残す。
