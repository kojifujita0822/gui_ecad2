# T-068 増分0 PoC — 自作パーツ形状編集キャンバスの操作感検証

作成: 2026-07-24（侍）。家老采配「T-068増分0のPoC実装」に対する成果。
対象: 隠密設計書`docs/ecad2-t068-increment0-poc-design-onmitsu.md`（§3の6論点、§4の分岐点3点は
すべて殿裁定=案A確定済み）。

## 目的

自作パーツ管理・編集UI（T-068、GuiEcadのパーツエディタ相当）の形状編集キャンバス（増分3、高リスク
領域）が、ecad2既存の描画基盤（`IRenderer`/`WpfRenderer`/`GridGeometry`、`DrawingVisual`毎フレーム
再構築方式）を流用して実用的に成立するか、増分3本実装前に検証する。

## 実装内容

`T068PartEditorPoc/PartEditorCanvas.cs`（`FrameworkElement`派生、`LadderCanvas.cs`と同型の
`VisualCollection`+`DrawingVisual`方式）に、設計書§3の6論点すべてを実装した。

| # | 論点 | 実装 |
|---|---|---|
| 1 | 描画基盤の応答性 | 線・矩形・円のpress→drag→release単純ドラッグ確定。ゴムバンド線プレビューあり |
| 2 | 折れ線の作図操作 | クリック連打で頂点追加→右クリックで確定（殿裁定=案A、Enterキー確定は無し） |
| 3 | 弧の作図とPartArcマッピング | 外接矩形ドラッグ→`PartArc(Cx,Cy,R,StartDeg=180,SweepDeg=180,Ry,Rot=0)`（殿裁定=案A、半楕円弧のみ）。選択中はステータスバー下のテキストボックスでRy（縦半径）を事後調整可能 |
| 4 | 回転操作 | 単体プリミティブ・15度スナップ。GuiEcad原本どおり型ごとに異なる実装（線/折れ線=座標を回転して焼き込み、矩形/弧=`Rot`フィールドへ加算のみ、殿裁定=案A） |
| 5 | Undo/Redo単位設計 | `List<PartPrimitive>`のシャローコピーによるスナップショット方式。ドラッグ中は直接書換え、確定時のみ1エントリ積む |
| 6 | 座標変換・スナップ・ヒットテスト | `GridGeometry`（Margin=0基準の線形変換をパーツローカル座標へ転用）+ 1/16セルスナップ + Ctrl+ホイールでズーム(0.2〜8.0) + 中ボタンドラッグでパン。各プリミティブ種別ごとの点-線分距離ヒットテスト（矩形/弧は回転考慮、GuiEcad原本と同値のしきい値0.3セル） |

選択・移動は殿裁定の分岐点2（案A=頂点ハンドル無し、プリミティブ全体の平行移動のみ）どおり実装。

## 技術的な発見（設計書からの逸脱と対処）

1. **`PartDrawing`（`Ecad2.Core.Rendering`）は`internal`修飾のためPoCから参照不可**と判明
   （設計書は「そのまま流用」を想定していたが、アクセス修飾子までは確認していなかったと見られる）。
   `Core層は無改変（設計書§6方針）`を厳守するため、同等の描画変換ロジックを`PartEditorCanvas.
   DrawPrimitive`へ複製した（switch文60行程度、Core層の実装自体は変更していない）。
2. **`GridGeometry`は「グリッド全体の行/列インデックス」用の型**であり、パーツローカル座標
   （原点=最左ポート・行中心線、任意の実数値）とは意味がやや異なるが、`Margin=0基準・CellMm
   固定`の線形変換自体は共通のため、`X(double)`メソッドをX/Y双方向に転用する形でそのまま流用できた
   （Core層は無改変）。

## 重要な所見: Undo/Redoの単位設計バグ（実装中に自己発見・修正）

当初、移動/回転の確定処理（`CommitMove`/`CommitRotate`）で「その時点の`_primitives`」を
Undoスタックへ積む実装にしていたが、これは**変更後の状態**を積んでしまう設計ミスだった
（ドラッグ中に`_primitives`を直接書き換え続けるため、確定時点では既に新しい値になっている）。
Undoを実行すると「変更後の状態」に戻るだけで実質何も変わらない、というバグを実装完了後の
自己レビューで発見した。

**対処**：ドラッグ**開始時点**で`_primitives`のスナップショットを別途保持しておき（
`_dragSnapshotBeforeChange`）、確定時にはその開始時点のスナップショットをUndoスタックへ積むよう
修正した。新規追加・削除（`CommitAdd`/`DeleteSelected`）は呼び出し時点の`_primitives`がそのまま
「変更前」の状態のため元の実装のままで正しい——**ドラッグ系（連続書き換え）と単発コマンド系
（追加/削除）とでUndo記録のタイミングが本質的に異なる**、という増分3設計へ持ち越すべき知見。

## 実行方法

```
dotnet run --project poc/t068-part-editor-poc/T068PartEditorPoc
```

- ツールバーのRadioButtonで選択/線/折れ線/矩形/円/弧/回転を切替
- 折れ線はクリックで頂点追加、右クリックで確定（Escで頂点リストを破棄）
- 弧選択中は下部のテキストボックスでRy（縦半径、セル単位）をEnterで反映
- Ctrl+ホイールでズーム、中ボタンドラッグでパン
- Delete=選択中プリミティブ削除、Ctrl+Z=元に戻す、Ctrl+Y=やり直し、Esc=作図中ドラフトの取消
- ステータスバーにツール・選択index・プリミティブ数・Undo/Redoスタック数・ズーム倍率を表示

## 構成

- `T068PartEditorPoc/PartEditorCanvas.cs` — 中核。座標変換・マウス操作・ヒットテスト・回転・
  Undo/Redo・描画（`PartDrawing`相当ロジックの複製）をすべて含む
- `T068PartEditorPoc/MainWindow.xaml(.cs)` — ツールバー・ステータス表示のホストウィンドウ
